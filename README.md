## :heavy_check_mark: 功能特性

- **保持条理与专注！** 用子任务、项目和标签规划与归类任务，并按需着色。
- 使用 **时间块（timeboxing）** 并 **追踪时间**。轻松创建工时表与工作汇总，方便导出到公司的时间追踪系统。
- 帮助你 **养成健康且高效的习惯**：
  - **休息提醒** 会在该休息时提醒你离开屏幕。
  - **反拖延功能** 在你真正需要时帮你理清视角。
  - 需要更多专注？随时可用的 **番茄钟计时器**。
  - **收集个人指标**，看看哪些工作节奏需要调整。
- 与 **Jira**、**Trello**、**GitHub**、**GitLab**、**Gitea**、**OpenProject**、**Linear**、**ClickUp** 和 **Azure DevOps** 集成。自动导入分配给你的任务，在本地细化计划，自动创建工作日志，并在有变更时立即通知你。
- 基础 **CalDAV** 集成。
- 通过 **SuperSync**、**Dropbox** 和 **WebDAV** 在多设备间备份与同步数据。SuperSync 是我们自有的端到端加密同步服务，也可[自行托管](https://github.com/super-productivity/super-productivity/tree/master/packages/super-sync-server)。
- 为任务和项目附加上下文信息。创建 **笔记**、附加 **文件**，或创建项目级 **书签**（链接、文件乃至命令）。
- Super Productivity **尊重你的隐私**，**不会收集任何数据**。无需账号或注册。**数据存哪儿由你决定！**
- **免费** 且 **开源**，并将始终如此。

## 文档：人工 vs 自动

有两套 Wiki：GitHub 托管的官方版，以及由 [DeepWiki.com](https://deepwiki.com/super-productivity/super-productivity) 自动生成的版本。人工整理的版本更稳定、更易接近，从更偏用户的视角帮助你理解应用；而 DeepWiki 更适合解释代码本身，对除此之外的上下文关心较少。

<div style="display: flex; gap: 10px; align-items: flex-start;">

  <div style="flex: 1;">
    <h3>官方 Wiki</h3>
    <p>
      更倾向于维护本地文档，而不是依赖外部服务。
      也更希望文档随代码变更同步更新，例如
      <a href="https://github.com/super-productivity/super-productivity/commit/7a51d4b06e414fdcc48e4999197a93eee9cd09da">这次提交</a>
      所示。
    </p>
    <p>
      对 <code>./docs/wiki</code> 内文件的变更会在 CI 中先做 lint，再自动同步到
      GitHub 托管的官方 Wiki。
    </p>
    <p>
      长期目标是在 Wiki 内容与结构成熟、剩余「遗留文档」被重写或移除后，迁移到
      Docusaurus。已有一些自动化在开发中，用于缩小已发布文档与代码状态的差距，同时保留人工把关。
    </p>
