# 任务笔记（Task Notes）

Super Productivity 中的任务笔记是集成的、感知上下文的文档，用于补充而非替代外部文档工具。它们专为在规划与执行过程中即时捕获和检索与任务相关的信息而设计，以便你将上下文集中在一处，而无需切换到单独的应用。

应用还支持**项目笔记**——附着于项目而非单个任务的笔记，用于项目级上下文。参见 [[4.06-Project-View]]。本概念聚焦于**任务笔记**：任务上的笔记字段，用于任务详情面板与专注模式。关于笔记如何融入任务模型，参见 [[4.09-Task-Attributes]]。

## 与外部文档工具相比的角色

任务笔记提供轻量、附着于任务的文档，并留在工作流内。当你打开任务或在专注模式下处理它时，笔记始终可用，因此你不必离开应用去查找自己写下的内容。外部工具（例如 Jira、GitHub 或你自己的 wiki）处理更广泛的项目文档、规格说明与长期知识；Super Productivity 的笔记面向**即时**上下文：你希望从此任务得到什么、你计划如何做，以及你在工作过程中捕获的内容。应用可通过 WebDAV 或 Dropbox 同步数据（包括笔记）以进行备份，但任务笔记的主要角色是即时的、与任务相关的文档，而非完整的知识库。

## 规划 vs 执行中的用法

任务笔记同时支持规划与执行，在各阶段侧重点不同。

**规划阶段：** 当你创建或打开任务时，可以使用**默认笔记模板**（可在 [[3.02-Settings-and-Preferences]] 中配置）来引导结构化思考。模板可包含诸如“我现在如何最好地完成它？”和“我想要什么？”等提示，使新任务以一致的结构开始。模板只是起点——你可以编辑或替换它。这让你在需要时获得结构，而不会强制采用僵化格式。

**执行阶段：** 在工作过程中，笔记充当**动态工作文档**。在专注模式下，你可以就地查看和编辑任务的笔记，从而无需离开任务上下文即可实时更新。你可以添加检查清单、记录决策，或随手记下下一步。内联 markdown 编辑器同时支持结构化检查清单（应用可在 UI 中将其视为检查清单）与自由格式内容，因此你可按需混合使用列表与散文。

当任务的笔记被识别为检查清单时，任务会在其控件中显示小型进度指示器（例如 `2/5`），以便你无需打开任务即可一眼看出检查清单进展到哪一步。当每一项都勾选完成后，指示器会切换为完成状态；点击它会打开该任务的笔记。

在笔记编辑器中查看检查清单时，你可以通过**检查清单操作**菜单（编辑器控件旁的列表图标）直接管理它，一步完成 **全部勾选（Check all）**、**全部取消勾选（Uncheck all）** 或 **清除已完成（Clear completed）** 项。这些操作仅在笔记被识别为检查清单时出现。

## 结构化 vs 自由格式：设计如何平衡两者

笔记系统在结构与灵活性之间取得平衡，使笔记既能作为规划辅助，也能作为灵活的执行文档。

1. **模板引导的结构** — 默认笔记模板为新任务提供一致的起始形态（例如规划问题）。模板可按任务编辑，因此你在有帮助的地方保留结构，在不需要的地方丢弃它。

2. **Markdown 灵活性** — 笔记支持标准 markdown：标题、列表、粗体、链接等。你可以撰写自由格式文本，或使用应用可视为检查清单的列表语法。渲染后的检查清单项可通过复选框或项目文本切换，而链接保持其正常链接行为。你不会被锁定在固定表单中。

3. **感知上下文的存储** — 笔记以简单文本形式存储，附着于特定任务（或对于项目笔记，附着于项目）。这使它们易于查找，并保持数据模型简单——没有沉重的模式，只是绑定到正确上下文的内容。项目笔记与任务笔记也可通过全局搜索（Shift+F）找到，让你可以快速跳转并高亮跨不同项目的笔记内容。

4. **最小模式** — 笔记模型保持最小：内容、可选的图片引用，以及基本元数据。这避免过度结构化，并使笔记适合临时快速捕获，同时在你需要时仍支持模板与检查清单。

结果是，笔记可以作为结构化规划工具，也可以作为灵活的执行文档，而无需复杂笔记模式带来的开销。

## 同步与备份

任务笔记与项目笔记是你 Super Productivity 数据的一部分。当你使用同步（例如 WebDAV 或 Dropbox）时，笔记会包含在同步数据中，因此它们会被备份并可在其他设备上使用。同步支持备份与连续性；它不会改变笔记的主要用途，即仍是即时的、与任务和项目相关的文档，而非完整外部知识管理系统的替代品。
