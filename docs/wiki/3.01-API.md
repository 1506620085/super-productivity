# APIs

本参考是使用 Super Productivity API 的入口。应用暴露**四套 API 系统**：**Sync Server REST API**（用于数据同步）、**Local REST API**（用于从本地脚本控制桌面应用）、**Plugin API**（用于扩展应用），以及 **URL Scheme Actions**（用于从应用外部触发少数任务操作，例如 iOS Shortcut）。本参考概括全部四套；完整的请求/响应 schema 与示例位于仓库中（Sync Server：`packages/super-sync-server/`；Plugin API：`packages/plugin-api/` 与 `docs/plugin-development.md`；Local REST API：`src/app/core/electron/local-rest-api-handler.service.ts`；URL Scheme Actions：`electron/protocol-handler.ts` 与 `src/app/features/tasks/util/parse-app-uri-task-action.ts`）。

## 1. Sync Server REST API

Sync Server 是内置 SuperSync 提供方所使用的基于操作的同步服务。它不是 WebDAV。面向用户的同步选项见
[[2.08-Choose-Sync-Backend]] 与 [[2.09-Configure-Sync-Backend]]。

### 认证与授权

受保护的 Sync Server 端点使用 **JWT Bearer** 认证：
`Authorization: Bearer <token>`。生产环境的账户创建与登录使用
通行密钥（passkeys）或邮件魔术链接；没有基于密码的
`POST /api/register` 或 `POST /api/login` 路由。仅邮箱注册从
`POST /api/register/magic-link` 开始。

关于当前端点用途、令牌生命周期与安全属性，请使用
[authentication authority](https://github.com/super-productivity/super-productivity/blob/master/packages/super-sync-server/docs/authentication.md)。
[executable routes](https://github.com/super-productivity/super-productivity/blob/master/packages/super-sync-server/src/api.ts)
拥有确切的请求与响应 schema。

### 同步端点

所有同步路由都需要认证。稳定表面包括操作
上传/下载、完整状态上传、状态、设备列表
（`GET /api/sync/devices`）、数据删除、恢复点列表与恢复。
`POST /api/sync/snapshot` 是上传端点；没有
`GET /api/sync/snapshot`。令牌替换（`POST /api/replace-token`，位于
账户路由而非 `/api/sync` 下）会使该账户的每一个现有令牌失效，
并为调用客户端返回新令牌——它支撑应用的“注销其他设备”操作；没有按设备撤销。

使用
[Sync Server architecture](https://github.com/super-productivity/super-productivity/blob/master/packages/super-sync-server/docs/architecture.md)
了解端点用途与可执行所有者。确切路由、限制、错误码
与线上 schema 位于
[`sync.routes.ts`](https://github.com/super-productivity/super-productivity/blob/master/packages/super-sync-server/src/sync/sync.routes.ts)
与
[shared HTTP contract](https://github.com/super-productivity/super-productivity/blob/master/packages/shared-schema/src/supersync-http-contract.ts)。

## 2. Plugin API

Plugin API 通过全局 `PluginAPI` 对象暴露。插件是
特权扩展，而非强沙箱应用：宿主侧
`plugin.js` 代码在应用渲染进程中运行，iframe 插件与宿主同源。
用户信任模型见 [[2.21-Manage-Plugins]]，平台差异见
[[3.05-Web-App-vs-Desktop]]。完整类型与开发指南位于 `packages/plugin-api/src/types.ts` 与
`docs/plugin-development.md`。

### Plugin API 分类

**数据 — 任务：**

- `getTasks()`、`getArchivedTasks()`、`getCurrentContextTasks()` — 读取任务。
- `getSelectedTask()` — 读取任务详情面板中选中的任务，或 `null`。
- `getFocusedTask()` — 读取当前聚焦的任务行，或 `null`。行焦点是瞬时的，当焦点移到别处（包括移入 iframe 侧边面板）时会清除；持久的侧边面板上下文请使用 `getSelectedTask()`。
- `addTask(taskData)`、`updateTask(taskId, updates)`、`deleteTask(taskId)` — 创建/更新/删除。在 `addTask` 上，`parentId` 必须引用顶层任务；传入子任务的 id 会被拒绝，因为模型只有两层深。`updateTask` 拒绝 `parentId` 与 `subTaskIds` — 那里不支持重新设定父级；请使用 `batchUpdateForProject`，它会维护链接的两侧。
- `batchUpdateForProject(request)` — 对项目进行批量创建/更新/删除/重排。
- `reorderTasks(taskIds, contextId, contextType)` — 重排任务。

**数据 — 项目：**

- `getAllProjects()`、`addProject(projectData)`、`updateProject(projectId, updates)`。

**数据 — 标签：**

- `getAllTags()`、`addTag(tagData)`、`updateTag(tagId, updates)`。

**数据 — 简单计数器：**

- `setCounter(id, value)`、`getCounter(id)`、`incrementCounter(id, incrementBy)`、`decrementCounter(id, decrementBy)`、`deleteCounter(id)`、`getAllCounters()`。

**UI：**

- `showSnack(snackCfg)`、`notify(notifyCfg)` — 通知。
- `openDialog(dialogCfg)` — 打开插件对话框，解析为所点击按钮的标签，若对话框被关闭则为 `undefined`。宿主按允许列表对 `htmlContent` 做消毒，保留语义 HTML、表单控件与布局样式，同时移除脚本、事件处理器、不安全 URL、内联 `<svg>`，以及包含 `url(` 的样式。
- `showIndexHtmlAsView()` — 显示插件 UI。

**注册（仅主插件上下文；不在 iframe 中）：**

- `registerHeaderButton(config)`、`registerMenuEntry(config)`、`registerShortcut(config)`、`registerSidePanelButton(config)`、`registerHook(hook, handler)`。

**持久化：**

- `persistDataSynced(dataStr)`、`loadSyncedData()`、`getConfig()` — 插件专用存储与配置。

**高级：**

- `executeNodeScript(request)` — 运行 Node.js 脚本（仅 Electron，需 `nodeExecution` 权限与用户同意）。
- `dispatchAction(action)` — 分发 NgRx 操作（允许的子集）。
- `downloadFile(filename, data)`、`isWindowFocused()`、`onWindowFocusChange(handler)`。

### Hooks（事件）

插件可为以下事件注册处理器：`taskCreated`、`taskComplete`、`taskUpdate`、`taskDelete`、`currentTaskChange`、`finishDay`、`languageChange`、`persistedDataChanged`、`action`、`anyTaskUpdate`、`projectListUpdate`。载荷类型定义在 `plugin-api` 类型中（`HookPayloadMap`）。

`persistedDataChanged` 在初始启动加载之后、该插件持久化数据发生任何变更（本地写入、远程同步、批量导入）时触发。载荷为 `void`；重新调用 `loadSyncedData(key?)` 以获取新数据。无注册时重放，快速变更间无顺序保证——处理器必须幂等。

### 插件数据类型

核心类型（Task、Project、Tag 等）与批量类型（`BatchUpdateRequest`、`BatchUpdateResult`、`BatchOperation` 等）位于 `packages/plugin-api/src/types.ts`。

### 插件清单

插件需要 `manifest.json`。使用
[`PluginManifest`](https://github.com/super-productivity/super-productivity/blob/master/packages/plugin-api/src/types.ts)
作为当前字段契约，而不是将其必填与可选字段复制到 wiki。

插件包通常包含用于宿主侧行为的 `plugin.js`。仅 iframe 的插件在
设置 `iFrame: true` 且包含 `index.html` 时可省略 `plugin.js`。

### 插件权限

- **nodeExecution：** `executeNodeScript()` 所需（仅 Electron）。
  内置与上传的插件均可请求。Electron 主进程在授予访问前会显示
  原生同意对话框；上传的插件被标为具有完整机器访问权限的
  未验证第三方代码。
- 其他权限可能限制特定 API 方法；见插件开发指南。

### Iframe API 表面与信任边界

iframe 插件收到注入到 `index.html` 中的过滤后的 `window.PluginAPI` 对象。
该对象是任务/项目/标签 API、对话框、通知、导航、持久化、注册、计数器与
操作分发的受支持接口。当桌面应用授予 `nodeExecution` 时，
`executeNodeScript` 通过宿主桥接代理。

iframe 使用 `allow-same-origin`，这是打包桌面应用所要求的。
同源 iframe 代码可直接访问父级，因此过滤后的
`postMessage` 桥接是便利与兼容接口，而非
安全边界。当前 API 表面与安全注意事项见 `docs/plugin-development.md`。

## 3. Local REST API

Local REST API 允许外部脚本与工具与正在运行的 Super Productivity 桌面应用交互。它运行在 `http://127.0.0.1:3876`，默认禁用。在 **Settings → Misc → Enable local REST API** 中启用。

对于开发脚本，`SP_FORCE_LOCAL_REST_API=1 npm start` 可在不更改已持久化用户设置的情况下启动 Local REST API。此覆盖仅在 `NODE_ENV=DEV` 中有效。在干净配置上，设置 `SP_FORCE_LOCAL_REST_API_TOKEN=<token>` 可显式选择 Bearer 令牌；否则应用会生成临时开发令牌并打印到终端（stdout，从不写入可导出的应用日志）。

### 前提条件

- **仅 Electron 桌面应用**（Web 或移动端不可用）
- 必须在设置中启用，除非使用开发覆盖
- 应用必须正在运行且渲染进程已就绪

### 认证

每个请求必须以 Bearer 令牌携带访问令牌：

```bash
# Keep the token out of the command line: arguments are visible to every process
# on the machine (`ps`, /proc). Put the header in a file only you can read.
(umask 077; printf 'Authorization: Bearer %s\n' "$SP_TOKEN" > ~/.sp-api-header)

# --noproxy is not optional: curl honours http_proxy/ALL_PROXY even for
# 127.0.0.1, so without it a configured proxy receives your token.
curl --noproxy 127.0.0.1 -H "@$HOME/.sp-api-header" http://127.0.0.1:3876/tasks
```

`-H @file` 需要 curl 7.55.0 或更新版本。在旧版本上，将同一行放入
`0600` 配置文件，形式为 `header = "Authorization: Bearer <token>"`，并用
`--config` 传入。无论哪种方式，凭据都不会出现在进程表中。

启用 API 时会自动生成令牌，并显示在
**Settings → Misc → Access Token** 下，你也可以在那里重新生成。重新生成
会立即使先前令牌失效。

缺失、格式错误或错误的令牌返回 `401`，错误码为 `UNAUTHORIZED`，并带有
`WWW-Authenticate: Bearer` 头。`GET /health` 是唯一例外，保持
未认证，以便工具探测存活。

> 下方示例为简洁起见省略了 `Authorization` 头——除 `/health` 外每一个都需要它。

### 令牌保护什么、不保护什么

令牌按设备存储在 [[3.06-User-Data]] 文件夹内模式为 `0600` 的文件中，从不同步或导出。它关闭了
**机器上另一账户**，或无法读取该文件的沙箱进程与 API 通信的情况：此前，每个本地进程都能读取并修改你的全部任务。

有两项限制是有意为之，在启用 API 前值得了解：

- **以你身份运行的任何进程都能读取令牌文件**，因此也能读取你的任务。在单用户桌面上，这涵盖大多数进程。文件权限是账户之间的边界，不是你所运行程序之间的边界。
- **API 不会向客户端证明自身身份。** 端口固定且未受保护，因此在 Super Productivity _未_ 监听时绑定 `127.0.0.1:3876` 的进程——在应用启动前，或 API 关闭时——会收到下一个连接客户端的 `Authorization` 头，并可释放端口之后复用该令牌。`GET /health` 未认证，因此冒充者也能令人信服地回答存活探测。关闭此问题需要服务器在受保护传输上证明身份；重试或移动端口无济于事，因为冒充者在应用关闭时绑定该端口。

因此：仅在你信任每一个能绑定回环端口的账户的机器上启用 API，并将令牌视为凭据——若可能已暴露则重新生成。

### 基础 URL

```text
http://127.0.0.1:3876
```

### 响应格式

所有响应均为带有一致信封的 JSON：

```typescript
// Success
{ "ok": true, "data": <response data> }

// Error
{ "ok": false, "error": { "code": "<ERROR_CODE>", "message": "<description>" } }
```

### 任务端点

| 方法   | 路径                 | 说明                               |
| ------ | -------------------- | ---------------------------------- |
| GET    | `/tasks`             | 列出任务（可带可选筛选）           |
| GET    | `/tasks/:id`         | 按 ID 获取任务                     |
| POST   | `/tasks`             | 创建任务                           |
| PATCH  | `/tasks/:id`         | 更新任务                           |
| DELETE | `/tasks/:id`         | 删除任务                           |
| POST   | `/tasks/:id/start`   | 开始任务（设为当前）               |
| POST   | `/tasks/:id/archive` | 归档任务                           |
| POST   | `/tasks/:id/restore` | 恢复已归档任务                     |

**GET /tasks 查询参数：**

| 参数          | 类型    | 说明                                                              |
| ------------- | ------- | ----------------------------------------------------------------- |
| `query`       | string  | 按标题筛选（不区分大小写，包含匹配）                              |
| `projectId`   | string  | 按项目 ID 筛选                                                    |
| `tagId`       | string  | 按标签 ID 筛选。使用 `TODAY` 表示安排在今天的任务                 |
| `includeDone` | boolean | 包含已完成任务（默认：false）                                     |
| `source`      | string  | `"active"` \| `"archived"` \| `"all"`（默认：`"active"`）         |

**示例：**

```bash
# List all active tasks
curl http://127.0.0.1:3876/tasks

# List archived tasks
curl "http://127.0.0.1:3876/tasks?source=archived"

# Search tasks containing "meeting"
curl "http://127.0.0.1:3876/tasks?query=meeting"

# List tasks scheduled for today
curl "http://127.0.0.1:3876/tasks?tagId=TODAY"

# Create a task
curl -X POST http://127.0.0.1:3876/tasks \
  -H "Content-Type: application/json" \
  -d '{"title": "Buy groceries", "projectId": "INBOX_PROJECT"}'

# Create a subtask (parent must be a top-level task; the subtask inherits
# the parent's projectId and cannot have its own tags)
curl -X POST http://127.0.0.1:3876/tasks \
  -H "Content-Type: application/json" \
  -d '{"title": "milk", "parentId": "PARENT_TASK_ID"}'

# Update a task
curl -X PATCH http://127.0.0.1:3876/tasks/task-id \
  -H "Content-Type: application/json" \
  -d '{"title": "Updated title"}'

# Archive a task
curl -X POST http://127.0.0.1:3876/tasks/task-id/archive
```

**POST /tasks 请求体字段：**

| 字段                 | 说明                                                                                                                                                                                                                                                                                              |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `title`（必填）      | 非空字符串                                                                                                                                                                                                                                                                                        |
| `parentId`           | 将任务创建为该顶层任务的子任务。父任务缺失返回 404；父任务本身是子任务返回 400。新子任务继承父任务的 `projectId`，且从不会有自己的标签——与 `parentId` 一起提供 `projectId` 或 `tagIds` 会返回 400 `UNSUPPORTED_FIELD`。                                                                           |
| `subTaskIds`         | 创建时不支持——返回 400 `UNSUPPORTED_FIELD`。先创建父任务，再用 `parentId` 创建每个子任务。                                                                                                                                                                                                         |
| 其他允许字段         | `notes`、`isDone`、`timeEstimate`、`timeSpent`、`projectId`、`tagIds`、`dueDay`、`dueWithTime`、`plannedAt`                                                                                                                                                                                       |

**PATCH /tasks/:id — 受限字段：**

`parentId` 与 `subTaskIds` 不能通过 `PATCH` 设置（返回 400 `UNSUPPORTED_FIELD`）。此 API 不支持对现有任务重新设定父级；请改为删除并重新创建任务。

更改顶层任务的 `projectId` 会原子性地移动该任务及其全部子任务。目标必须是已有的活动项目；缺失或已归档的目标返回 404 `PROJECT_NOT_FOUND`。子任务的 `projectId` 从父任务继承，不能直接更改（400 `UNSUPPORTED_FIELD`）；回显其未更改的继承值在 GET-to-PATCH 往返中可被接受。项目移动可与同一 PATCH 请求中的其他可写字段组合。

### 专注状态端点

| 方法 | 路径     | 说明                                                    |
| ---- | -------- | ------------------------------------------------------- |
| GET  | `/focus` | 获取当前只读的 Focus Mode 计时器状态与模式              |

`GET /focus` 报告桌面应用使用的权威 Focus Mode 状态。它
不暴露任务内容，也不提供开始、暂停、
继续、跳过或取消专注会话的控制。

```bash
curl http://127.0.0.1:3876/focus
```

**响应数据：**

```typescript
{
  mode: 'Flowtime' | 'Pomodoro' | 'Countdown';
  cycle: number;
  isSessionDone: boolean;
  timer: null | {
    purpose: 'work' | 'break';
    status: 'running' | 'paused' | 'done';
    isOvertime: boolean;
    isLongBreak: boolean;
    elapsedMs: number;
    remainingMs: number;
    durationMs: number;
  };
}
```

`timer` 在不存在工作或休息计时器时为 `null`。已完成的工作会话由
`timer: null` 与 `isSessionDone: true` 表示；已完成的休息会保留其
休息计时器且 `status: 'done'`。其他活动计时器状态为 `running` 或 `paused`。
`isSessionDone` 反映当前 Focus Mode 屏幕，因此在关闭叠加层后
仍可保持为 true，直到另一专注操作更改屏幕。
`isOvertime` 与 `status` 独立，因此在加班工作会话暂停时仍为 true。
Flowtime 计时器没有倒计时时长，因此其 `remainingMs`
为零，而其状态仍为 `running` 或 `paused`。

`cycle` 是 Pomodoro 使用的从 1 开始的计数器。仅完成一次 Pomodoro 工作
会话会推进它，因此在该会话随后的休息期间它已推进。
切换到 Flowtime 或 Countdown 会保留当前值，但这些模式不会
推进它。Focus Mode 状态不持久化，因此在应用重启以及用户
显式重置 Pomodoro 周期计数时，周期重置为 `1`。

### Local REST API 备注

- **仅 Electron：** Local REST API 仅在桌面应用中可用。
- **认证：** 除 `/health` 外每个请求都需要 Bearer 访问令牌，并叠加仅 localhost 绑定。
- **端口：** 固定为 `3876`；v1 中不可配置。
- **超时：** 渲染进程响应 15 秒。

## 4. URL Scheme Actions

两项任务操作可通过应用现有的自定义 URL scheme 到达，无需先打开应用 UI：**添加任务**与**完成任务**（按标题匹配）。面向外部自动化——尤其是 iOS Shortcut 的 “Open URLs” 操作（也使其可通过 Siri 到达，见下文）以及 Android 自动化应用——但在任何可打开 URL 的地方均可使用。

Web（浏览器）构建中不可用，因其没有 URL scheme 注册。

### 平台与 Scheme

| 平台                | Scheme                          | 示例                                                        |
| ------------------- | ------------------------------- | ----------------------------------------------------------- |
| iOS（Capacitor）    | `com.super-productivity.app://` | `com.super-productivity.app://create-task?title=Buy%20milk` |
| Android（Capacitor）| `com.super-productivity.app://` | `com.super-productivity.app://create-task?title=Buy%20milk` |
| 桌面（Electron）    | `superproductivity://`          | `superproductivity://create-task?title=Buy%20milk`          |

两种 scheme 已为其他用途注册（移动端的 OAuth 回调；桌面的全局快捷键与窗口可见性操作）——这些是同一 scheme 上另外两个已识别的操作，而非新的注册。

使用小写的操作名。在 Android 上，操作系统对声明的 host 区分大小写匹配，因此 `://Create-Task` 根本无法解析；iOS 与桌面注册整个 scheme 并在应用中将操作转为小写，但小写是唯一处处可用的形式。

### 操作

**添加任务** — 所有平台上的操作 `create-task`（桌面也接受将标题作为路径段，`create-task/<title>`，与自 v14.2.4 起已有桌面操作匹配——其标题处理在此变更，见下方 Short Syntax 说明）。不是 `add-task`：桌面的 `add-task` 协议操作已存在，且做的是无关之事（打开快速添加任务输入栏）。

| 查询参数    | 必填 | 说明                                                                                                                                      |
| ----------- | ---- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `title`     | 是   | 新任务的标题。去除首尾空白；仅空白会被拒绝（不添加任务）。最长 300 字符（去除空白后）。                                                   |
| `notes`     | 否   | 任务备注。最长 100,000 字符。                                                                                                             |
| `projectId` | 否   | 目标项目 ID。若不匹配已有项目，操作失败并报错（不添加任务）。                                                                             |

**Short Syntax _不会_ 被解析**（见 [[3.04-Short-Syntax]]）：标题中的 `+Project`、`#tag` 或 `@date` 等标记会原样存储，而不是创建/分配项目、标签或截止日期（首尾空白仍会去除）。URL 是不受信任的外部内容，因此——与邮件拖放导入一样——不能静默创建标签/项目或覆盖显式的 `projectId`。使用 `projectId` 参数设置项目。

> **行为变更：** 已有的桌面 `create-task` 操作（自 v14.2.4 起提供）此前会像手动输入任务一样解析标题上的 Short Syntax。自本次变更起，所有平台都将标题原样存储。用 `projectId` 指定项目；`+`/`#`/`@` 标记不再被解释。

没有显式 `projectId` 时，任务会添加到应用中当前活动的项目/标签/上下文——冷启动时是上次打开的，不一定是 Inbox。传入 `projectId` 以获得确定性位置。

**完成任务** — 所有平台上的操作 `complete-task`。

| 查询参数 | 必填 | 说明                                                                                                                                                                                         |
| -------- | ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `title`  | 是   | （去除空白、不区分大小写）匹配活动（非归档）项目中的非子任务、未完成任务。仅作查找针，从不存储，因此不受 create-task 长度上限约束。                                                         |

优先精确的不区分大小写标题匹配；若没有，则使用不区分大小写的子串匹配，但仅当恰好一项任务匹配时。若没有任务匹配，或有多个同样合理的子串匹配，操作失败并报错，而不是猜测。

**示例：**

```text
com.super-productivity.app://create-task?title=Buy%20milk&notes=2%25%20fat&projectId=proj-1
com.super-productivity.app://complete-task?title=Buy%20milk

superproductivity://create-task?title=Buy%20milk
superproductivity://complete-task?title=Buy%20milk
```

### 通过语音助手触发

- **Siri（iOS）：** 在 Apple Shortcuts 应用中创建 Shortcut——“Ask for Input”（文本）后接 “Open URLs”，使用 `com.super-productivity.app://create-task?title=` 并追加输入——然后按名称调用：“Hey Siri, \<shortcut name\>”。Siri 口述标题，URL 打开应用并添加任务。查询参数值必须 URL 编码；Shortcuts 的 “URL Encode” 操作可处理含空格或特殊字符的标题。
- **Google Assistant / Gemini（Android）：** 此应用没有直接语音集成——Google 于 2023 年移除了第三方笔记/列表的 Assistant 集成，而 Gemini 的后继机制（AppFunctions）尚无公开的第三方集成路径（截至 2026-08）。Android 自动化应用（例如 Tasker、Automate）可打开这些 URL，从其自身触发器创建任务。

### 行为备注

- 所有平台在成功（任务已添加/完成）或失败（无匹配/歧义任务、未知项目）时显示 snack 通知——从应用外部由 URL 触发时没有其他反馈通道。
- 在冷启动（应用尚未运行）期间收到的操作会排队，直到应用自身数据加载完成，因此绝不会与初始 hydration 竞态。
- 在 Android 上，打开 URL 会将应用带到前台（操作由主 activity 处理）；没有后台执行。
- Web（浏览器）构建中不可用——见 [[3.05-Web-App-vs-Desktop]]。

## 5. 版本控制与兼容性

### Schema 版本控制（同步）

操作与快照携带 `schemaVersion`。当前与最低
支持版本，以及兼容性策略，定义在
`packages/shared-schema/src/schema-version.ts`。较新 schema 会被阻止，
而不是用复制的“版本跳过”余量来解释。

### 向量时钟

同步使用有界向量时钟进行冲突解决。规范大小与
修剪规则位于 `packages/sync-core/src/vector-clock.ts`；服务器侧输入
消毒位于 `packages/super-sync-server/src/sync/sync.types.ts`。服务器
可能在冲突解决期间临时接受更大的时钟再修剪，因此输入验证限制
不是存储的时钟大小。

### API 验证（Sync Server）

- 操作 ID：1–255 字符。客户端 ID：字母数字、下划线、连字符；最长 255。
- 实体类型：1–255 字符。Schema 版本：1–100。
- 按操作类型验证载荷（CRT、UPD、DEL、MOV、BATCH、SYNC_IMPORT 等）；见 `sync.types.ts` 中的 `validatePayload`。

## 一般备注

- **Sync Server：** 面向生产（JWT、速率限制、CORS、Helmet）。多实例部署有限制（例如 passkey challenge 存于内存；快照生成锁）；单实例是典型部署。
- **Plugin API：** 特权且非强沙箱；iframe、Web 与
  Electron 能力不同。见 [[2.21-Manage-Plugins]]、
  [[3.05-Web-App-vs-Desktop]]，以及仓库插件指南。
- **Local REST API：** 仅桌面、绑定 localhost，除 `/health` 外每个请求受 Bearer 访问令牌保护。用于自动化与脚本。平台差异见 [[3.05-Web-App-vs-Desktop]]。
- **URL Scheme Actions：** iOS 与 Android（Capacitor）以及桌面（Electron），不含 Web 构建。无认证——设备上任何能打开 URL 的进程都能触发，信任模型与同一 scheme 上现有的 OAuth 回调/全局快捷键操作相同。
- **进一步文档：** Sync Server README 与认证文档位于 `packages/super-sync-server/`；Plugin API 与示例位于 `packages/plugin-api/`、`docs/plugin-development.md`，以及 `packages/plugin-dev/` 下的示例插件；Local REST API 类型位于 `electron/shared-with-frontend/local-rest-api.model.ts`。
