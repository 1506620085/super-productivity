# 配置 Obsidian 以修改 Wiki

Obsidian 非常有用，但需要一些特定更改，才能产出与标准一致的 markdown。

## Git 集成

1. 你必须使用 `super-productivity/docs` 内的 `wiki` 目录打开新 vault。新笔记随后会显示为 `super-productivity/docs/wiki/note.md`（笔记不使用嵌套/子目录）。

2. 确保 Obsidian 数据不会泄漏到仓库中。对于仅本地排除，使用：  
   `echo ".obsidian" >> .git/info/exclude`

3. 确保每次提交前都进行 markdown lint。详情见 [[0.01-Style-Guide#linting]]。

4. 不要使用 "Git" 插件。

## 设置（与默认不同）

### Editor

**Strict Line Lengths**  
启用。  
在预览模式中查看笔记时，会正确显示 GH 如何渲染单行空格。可在行末添加两个空格来创建单行空格。

**Default Editing Mode**  
Source Mode。  
更好的设置是在一个窗格中使用 source mode，在另一个窗格中使用链接预览，以帮助减少 linter 会发现的问题数量。

**Show Line Numbers**  
启用。  
更容易查看空白空格的数量。

**Indent using Tabs**  
禁用。  
禁用此设置时，'tab' 键硬编码为 4 个空格，因此需要手动输入 2 个空格（尤其是嵌套列表时）。

### Files and Links

**Default Location for New Attachments**  
指定 `./assets` 目录。

**New Link Format**
Path from Vault 可确保没有重复笔记。

**Automatically Update Internal Links**  
启用。

## 插件

**Broken Links**
提交前运行。

**Paste image rename**  
默认设置。  
有助于保持图片命名一致。

**Linter**  
Obsidian Linter 插件是可选的。若使用，请将其配置为与
[[0.01-Style-Guide]] 一致，并将仓库的 CI 检查视为权威。
不要依赖复制的 Obsidian 配置，因为它可能随 CI 规则
变更而漂移。

**Safe Filename Linter**
将所有选项设为 "Empty String"。  
在提交前对所有文件运行此工具。
