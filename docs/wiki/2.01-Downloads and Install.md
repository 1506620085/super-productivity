## 已知问题与其他说明

### AppImages

若在 Ubuntu 上使用 AppImage 遇到问题，请参阅[此 issue 评论](https://github.com/super-productivity/super-productivity/issues/3193#issuecomment-2131315513)。

### Snap

要使用本地文件同步，需要手动连接 `home` 接口：`snap connect superproductivity:home`

数据持久化警告

卸载 snap 包时，存储在 `~/snap/superproductivity/common/` 中的所有用户数据（任务、项目、设置）可能会被删除。卸载前务必导出数据。若你更希望数据位于标准的 `~/.config/` 路径，可考虑使用 AppImage 或 .deb 包；或使用 Flatpak——其数据保存在 `~/.var/app/`，卸载时除非传入 `--delete-data`，否则会保留数据。

更多详情见 [issue #6031](https://github.com/super-productivity/super-productivity/issues/6031)。

### Flatpak

Flatpak 是受完整支持的安装包，与上方列出的其他格式同等——可从 [Flathub](https://flathub.org/en/apps/com.super_productivity.SuperProductivity/install) 安装。

若要同步到或备份到沙箱**外部**的文件夹，请使用 [Flatseal](https://flathub.org/apps/com.github.tchx84.Flatseal) 或 `flatpak override` 授予文件系统访问权限。否则应用会报告权限错误。`~/.var/app/com.super_productivity.SuperProductivity/` 内的路径无需额外权限。

数据位于沙箱中而非 `~/.config/`，因此以其他包格式安装的另一份应用看不到这些数据——见 [[3.06-User-Data]]。使用 `flatpak update com.super_productivity.SuperProductivity` 更新（无需 `sudo`）。

若应用内时钟相对你的 UTC 偏移量不正确——日程视图中的「现在」标记位置错误、时间整体偏移——说明沙箱在以 UTC 运行，因为 Flatpak 未能检测到主机时区。请显式强制指定：

```bash
flatpak override --user --env=TZ=Europe/Helsinki com.super_productivity.SuperProductivity
```

这个问题值得修复而不是忽略：应用根据本地时钟推导「今天」，因此时区偏移也会移动日切时间，并使接近午夜的计划任务与提醒落到错误的日期。

在 NixOS 上，根本原因在主机侧：Flatpak 从 `/etc/localtime` 符号链接的目标读取时区，而 NixOS 将其指向 `/etc/zoneinfo/…` 而非 `/usr/share/zoneinfo/…`，且没有 `/etc/timezone` 可供 Flatpak 回退。在 `configuration.nix` 中加入 `environment.etc."timezone".text = config.time.timeZone;` 可一次性修复所有 Flatpak 应用。见 [issue #9650](https://github.com/super-productivity/super-productivity/issues/9650)。

### Arch Linux

Super Productivity 现已作为 [`extra/super-productivity`](https://archlinux.org/packages/extra/x86_64/super-productivity/) 进入官方 Arch 仓库，由 Arch 从源码构建并维护。使用 `pacman -S super-productivity` 安装。

旧的 AUR 包 `superproductivity-bin`（重新打包的 `.deb`）已不再由本项目维护。若你之前安装过它，可按如下方式切换：

```bash
pacman -S super-productivity   # prompts to remove superproductivity-bin, which it conflicts with
```

`~/.config/superProductivity/` 中的数据在切换后会保留。

### Wayland

Snap 构建在 Wayland 会话中会自动使用 Electron 的 X11 渲染后端，以避免已知的 Mesa/EGL 启动失败。对于其他 Linux 包，若窗口空白或 GPU 进程反复启动失败，可尝试：

```bash
superproductivity --ozone-platform=x11
```

这会更改 Chromium 渲染后端；它不会启用任何额外的空闲检测功能，并可能放弃 Wayland 原生行为，例如分数缩放或原生输入法支持。
