# 看板视图（Board View）

**看板（board）** 提供了一种可视化的、基于列的任务组织方式。看板让你通过可配置的列（如看板法或艾森豪威尔矩阵）从不同视角查看和组织任务，而无需更改底层任务数据。

## 看板解决什么问题

看板解决的是**可视化任务组织**问题。它们提供灵活、可过滤的列，让你以不同方式查看任务——按状态、优先级、紧急程度，或你配置的任何其他标准——同时保持相同的底层任务。

例如，你可能有一个包含“待办（To Do）”、“进行中（In Progress）”和“完成（Done）”列的看板，或一个包含“紧急且重要”、“不紧急但重要”、“紧急但不重要”和“不紧急且不重要”四个象限的艾森豪威尔矩阵。

## 看板如何运作

看板由**面板（panels）**（列）组成。每个面板具有：

- **过滤器**，决定哪些任务出现在该面板中（按标签、完成状态、调度情况、一个或多个项目、是否在待办积压中等）
- **排序**，你可通过在面板内拖放任务来控制
- **自动更新**，在你于面板之间移动任务时修改任务属性

## 在列之间移动任务

当你将任务从一个面板拖到另一个面板时，应用会自动更新该任务以匹配目标面板的配置：

- **标签**会根据面板的标签过滤器添加或移除
- **完成状态**会根据面板设置更新（标记为完成或未完成）
- 若面板指定了项目，**项目分配**会更新
- **调度状态**会根据面板设置更新（已调度或未调度）

这意味着将任务移至“完成（Done）”面板会将其标记为完成，移至要求特定标签的面板会为该任务添加这些标签。

## 多个看板与任务归属

任务可以**同时出现在多个看板上**。这之所以可行，是因为：

- 每个看板面板根据其条件独立从活动项目中过滤任务
- 任务不存储它们属于哪些看板——归属是动态计算的
- 每个面板维护自己的排序，因此同一任务可以在不同看板上处于不同位置

例如，一个任务可能出现在艾森豪威尔矩阵看板的“紧急（Urgent）”列中，同时也出现在看板法的“进行中（In Progress）”列中，且在各自中的位置不同。

看板会包含从侧边栏隐藏的项目中的任务。隐藏的项目仍然是活动的；只有已归档项目才会从看板任务归属中移除。

## 看板 vs 项目 vs 标签

| 功能 | 看板 | 项目 | 标签 |
| --------------------- | ---------------------------------- | --------------------------------- | -------------------------------------- |
| **用途** | 带列的可视化组织 | 任务分组与结构 | 跨领域分类 |
| **与任务的关系** | 基于动态过滤的归属 | 直接分配（必需） | 直接分配（可选，可多个） |
| **视觉表现** | 基于列的布局 | 侧边栏中的树状视图 | 任务上的徽章显示 |
| **持久化** | 看板配置会被保存 | 项目数据与任务分配 | 标签数据与任务分配 |

看板在你现有的任务-项目-标签结构之上提供了一层灵活的可视化层。它们让你可以对同一批任务创建多个同时存在的视图，而无需复制底层任务数据。

## 默认看板

应用包含两个默认看板：

- **艾森豪威尔矩阵（Eisenhower Matrix）** — 按紧急程度与重要性组织任务（4 个象限）
- **看板法（Kanban）** — 按工作流阶段组织任务（待办、进行中、完成）

你可以创建带有自定义面板和过滤器的看板，以匹配你的工作流。
