# Issue 集成对比

本参考列出各 **issue 提供方** 支持的能力：issue 导入、状态流转、时间跟踪/工作日志提交、评论、子任务、附件、筛选选项、自动导入到积压、故事点、截止日期，以及其他特定于提供方的行为。可用于对比提供方，或了解启用某一提供方时期望的行为。

集成如何工作以及如何配置的概述，见 [[4.24-Integrations]] 与 [[2.07-Manage-Task-Integrations]]。**同步**提供方（WebDAV、Dropbox、SuperSync、本地文件）的对比见 [[3.08-Sync-Integration-Comparison]]。

## 核心能力（所有提供方）

每个 issue 提供方都支持相同的基本操作：检查集成是否启用、测试连接、在外部系统中打开 issue、按 ID 获取 issue、搜索 issue，以及将 issue 添加为应用中的任务。所有提供方还支持刷新已导入的任务，以便外部系统中的变更（标题、状态等）反映到本地。每个提供方都有可配置的 **轮询间隔**（或无），用于控制应用多久检查一次更新。除此之外，对状态流转、工作日志、评论、子任务、附件与筛选的支持取决于提供方与外部 API。

## 各提供方详情

### 1. Jira

- **Issue 导入：** 完整导入，支持 JQL 搜索。
- **状态流转：** 可配置工作流（例如 Open → In Progress → Done）。
- **工作日志：** 完整的工作日志提交与已用时间跟踪。
- **评论：** 评论跟踪与显示。
- **子任务：** 子任务关系跟踪与导入。
- **附件：** 附件映射与显示。
- **筛选：** 基于 JQL 的搜索；使用自定义 JQL 自动导入。
- **故事点：** 自定义字段支持。
- **指派：** 任务开始时重新指派；标为完成时更新指派人。

### 2. GitHub

- **Issue 导入：** 来自仓库的 issue 与 pull request。
- **状态流转：** 不支持（从应用侧 issue 为只读）。
- **工作日志：** 不支持。
- **评论：** 评论跟踪，可选按用户名筛选。
- **筛选：** 在仓库内搜索；积压查询；基于用户名的评论筛选。
- **自动导入：** 可配置的积压查询。

### 3. GitLab

- **Issue 导入：** 从项目完整导入（云端或自托管）。
- **状态流转：** 在 GitLab 中关闭时，issue 自动标为完成。
- **工作日志：** 曾支持；现已弃用。
- **评论：** 评论跟踪，可选按用户名筛选。
- **筛选：** 基于项目；范围（All、Assigned、Created）；自定义筛选参数。
- **故事点：** Weight 字段映射。
- **截止日期：** 支持截止日期。

### 4. Gitea

- **Issue 导入：** 来自仓库的 issue（自托管）。
- **状态流转 / 工作日志 / 评论 / 子任务 / 附件：** 不支持。
- **筛选：** 基于仓库；范围（All、Created by me、Assigned to me）；可选的逗号分隔标签允许列表（AND 匹配）与拒绝列表（NONE 匹配），均在客户端应用，并支持作用域标签（`scope/name`）。也适用于 Forgejo。`labels=` 查询仍会作为粗略预筛选发送到服务器，但 Gitea 的 `/repos/{owner}/{repo}/issues` 与 `/repos/issues/search` 端点在 AND 与 OR 语义上不一致（[go-gitea/gitea#33509](https://github.com/go-gitea/gitea/issues/33509)），因此客户端筛选才是权威来源。
- **自动导入：** 该项目最近 100 个 issue。

### 5. OpenProject

- **Issue 导入：** 带项目筛选的工作包。
- **状态流转：** 完整支持可配置工作流。
- **工作日志：** 带活动类型的时间条目提交。
- **评论：** 不跟踪。
- **子任务：** 不支持。
- **附件：** 支持附件上传。
- **筛选：** 范围（例如 created-by-me、assigned-to-me）；状态与用户名筛选。
- **故事点 / 时间预估：** 故事点字段与预估时间解析/显示。
- **截止日期：** 支持开始日期。
- **进度：** 完成百分比更新。

### 6. CalDAV

- **使用内容：** 应用仅请求 **VTODO** 组件。它**不**读取或显示 VEVENT（日历事件）。若日历同时有事件与任务，应用中只会出现任务（VTODO）。
- **认证：** **需要登录**（用户名与密码或等价凭证）到 CalDAV 服务器。
- **Issue 导入：** 从 CalDAV 导入任务/待办。子任务可选择性地随父任务一并导入。对于已导入的 VTODO，完成状态、标题与笔记各自可配置为 **关**、**仅拉取**、**仅推送** 或 **双向**。这使完成状态变更可从 CalDAV 拉取、推回，或双向同步。在 Super Productivity 中创建的任务**不会**作为新的 VTODO 上传。
- **状态流转：** 在配置中启用时支持。
- **工作日志 / 评论 / 子任务 / 附件：** 不支持。
- **筛选：** 基于分类的筛选。
- **笔记：** 支持任务笔记/描述。
- **截止日期：** 支持带时间的开始日期。
- **相关任务：** 任务关系跟踪。
- **URL 格式：** 对于 Nextcloud，请使用来自 **「复制私人链接」**（或 CalDAV URL）的 `https://<NC-URL>/remote.php/dav/calendars/<USER>/<CALENDAR_NAME>/`，而非订阅/导出链接。对于 Vikunja，请使用 Vikunja CalDAV 设置中显示的 principal URL，例如 `https://<VIKUNJA-URL>/dav/principals/<USER>/`，并将 CalDAV 资源设为项目名称或项目 ID。无有效 VTODO 的项会被跳过。

### 7. Calendar（iCal）

- **使用内容：** 应用仅从 iCal 源解析 **VEVENT** 组件。它**不**使用 VTODO（任务）。事件必须有有效的 **开始时间**（DTSTART）；否则会被跳过。包含全天事件（仅日期的开始）。
- **认证：** **无需登录。** 只需提供日历 URL（订阅或导出链接）。
- **Issue 导入：** 来自 iCal URL 的日历事件（VEVENT）。事件出现在 Schedule/Planner 中；事件描述成为任务笔记。**完成与时间/日期变更不会同步回去**——从应用角度看该源为只读；若你在应用中更改任务，外部日历不会更新。
- **状态流转 / 工作日志 / 评论 / 子任务 / 附件：** 不支持。
- **筛选：** 基于文本在事件标题中搜索。日历提供方设置还可对事件标题应用可选的不区分大小写的包含与排除正则表达式。包含筛选作为允许列表；排除筛选随后应用。
- **自动导入：** 当天事件。删除自动导入的事件任务会阻止该事件再次导入；使用 **撤销** 会同时恢复任务及其自动导入资格。
- **时间预估：** 事件时长用作任务时间预估。
- **截止日期：** 事件开始时间（全天或带时间）。
- **描述：** 事件描述作为任务笔记。
- **URL 格式（以 Nextcloud 为例）：** 使用 **「复制订阅链接」**，使 URL 为正确形式，例如 `https://<NC-URL>/remote.php/dav/public-calendars/<CALENDAR-ID>?export`。将其粘贴到应用的 **「iCal 源的 URL」** 下。**不要**使用「复制私人链接」——该格式用于 CalDAV，而非 iCal。
- **平台说明：** **在 Web 或 Android 应用中禁用** 设置会在浏览器与 Android 上抑制 iCal 请求，这些环境中 WebView 网络限制可能产生类似失败。

### 8. Redmine

- **Issue 导入：** 来自项目的 issue。
- **状态流转 / 工作日志 / 评论 / 子任务 / 附件：** 不支持。
- **筛选：** 基于项目；支持范围；任务搜索支持非拉丁主题匹配。
- **自动导入：** 该项目最近 100 个 issue。

### 9. Trello

- **Issue 导入：** 来自看板的卡片。
- **状态流转 / 工作日志 / 评论 / 子任务：** 不支持。
- **附件：** 附件映射与显示。
- **筛选：** 基于看板的筛选。
- **故事点：** 支持。
- **自动导入：** 自动将卡片导入积压。

### 10. Linear

- **Issue 导入：** 带团队/项目筛选的 issue。
- **状态流转：** 根据状态自动将 issue 标为完成。
- **工作日志 / 评论 / 子任务：** 不支持。
- **附件：** 附件映射与显示。
- **筛选：** 基于团队与项目。
- **自动导入：** 自动将 issue 导入积压。

### 11. Azure DevOps

- **Issue 导入：** 来自 Azure DevOps Boards 的工作项。
- **状态流转 / 工作日志 / 评论 / 子任务 / 附件：** 不支持。
- **筛选：** 基于项目；支持范围（All、Created by me、Assigned to me）；可选自定义 WIQL 查询用于自动导入。
- **自动导入：** 可配置的自动积压导入上限，最多 200 个工作项。可选 WIQL 查询可完全覆盖自动导入查询（范围、状态筛选与排序），例如按迭代路径、区域路径或工作项类型筛选。为空时使用基于范围的筛选。
- **截止日期：** 支持截止日期、目标日期或开始日期。

### 12. ClickUp

- **Issue 导入：** 带团队筛选的任务。
- **状态流转：** 根据状态自动将任务标为完成。
- **工作日志 / 评论：** 不支持。
- **子任务：** 完整的子任务支持与关系跟踪。
- **附件：** 附件映射与显示。
- **筛选：** 基于团队。
- **自动导入：** 自动将任务导入积压。

### 13. Plainspace

Plainspace 是 Super Productivity 自有的 **协作** 层（位于 [plainspace.org](https://plainspace.org) 的共享工作区），因此行为不同于上方以只读为主的 issue 跟踪器。你用个人 API 令牌（`pat_…`）连接一个 **Space**，该 Space 中**指派给你**的任务会导入到绑定的项目。

- **Issue 导入：** 已连接 Space 中指派给你的任务。工作视图中的 **认领池** 还会列出你可以认领到列表中的**未认领**任务。
- **状态流转：** **双向完成同步** — 本地完成任务会在 Plainspace 中标为完成，在 Plainspace 中完成的任务会在下次轮询时标为完成。
- **标题与排程：** **双向** — 本地重命名或重新排程任务会推回 Plainspace（`dueWithTime` ↔ `scheduledAt`），在 Plainspace 中的变更会在轮询时拉取。**重复**任务会在认领池与任务面板中标记；Plainspace 服务器会将排程推进到下一次发生。
- **工作日志 / 评论 / 子任务 / 附件：** 不支持。
- **筛选：** 按 Space（每个 Space 一个提供方实例）。
- **自动导入：** 指派的任务自动导入到绑定项目的积压；轮询间隔为 5 分钟。若任务**离开**你的 Plainspace 列表（取消指派或移除），会自动在本地移除。
- **共享项目：** 你可通过 **项目上下文菜单 → 在 Plainspace 上协作**，或在创建项目时通过 **在此项目上协作** 开关，将现有本地项目变为共享 Space。这会一步配置 Space 与绑定的 Plainspace 提供方。见 [[2.07-Manage-Task-Integrations]]。

## 实现说明

- **功能最广：** Jira 与 OpenProject 支持最多能力：可配置状态流转、工作日志提交与高级筛选。OpenProject 增加进度百分比与活动；Jira 增加 JQL、子任务与指派处理。
- **偏重评论：** GitHub 与 GitLab 提供扎实的 issue 导入与评论跟踪（可选按用户名筛选），但不支持工作日志提交；GitLab 的工作日志支持已弃用。
- **子任务支持：** 除 Jira 外，所列提供方中仅 ClickUp 支持完整的子任务导入与关系跟踪。
- **面向日历：** CalDAV 与 Calendar（iCal）面向日历/待办与事件集成（分类、事件时长、当天事件），而非完整的 issue 跟踪功能。它们**不可互换**：iCal 使用订阅 URL 且仅 VEVENT（事件），无需登录且不同步回去；CalDAV 使用服务器登录且仅 VTODO（任务），对已导入的 VTODO 按字段配置拉取与推送方向。它不会从 Super Productivity 中创建的任务新建 VTODO。使用错误的链接类型（例如在 iCal 中使用 Nextcloud「私人链接」，或在 CalDAV 中使用「订阅链接」）是集成无法工作的常见原因；iCal 与 CalDAV 概述见 [[4.24-Integrations]]。
- **自动导入与轮询：** 大多数提供方支持自动轮询更新，许多支持将新 issue 自动导入积压；确切行为（例如「最近 100」与自定义查询）因提供方而异。
- **协作与导入：** Plainspace 是唯一双向且面向协作的提供方——它双向同步完成状态、标题与排程，并允许你将本地项目共享为 Space。其他提供方主要是从外部跟踪器单向导入。

可选能力（例如子任务、附件、将更新发回外部系统）按提供方实现，取决于外部 API 支持什么。
