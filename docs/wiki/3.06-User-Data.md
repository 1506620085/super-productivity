# 用户数据

**用户数据（User Data）** 概念**仅适用于桌面（Electron）应用**。Web 应用将数据存储在浏览器存储（IndexedDB 与 localStorage）中。Web 与桌面差异见 [[3.05-Web-App-vs-Desktop]]。从用户视角了解导入、导出、备份与同步如何工作，见 [[4.23-Managing-Your-Data]]。

## 包含哪些数据

完整备份或导出是应用模型的可恢复快照：任务（活动与已归档）、项目、标签、时间跟踪状态、全局配置、备注、提醒、指标、简单计数器、规划器与看板状态、任务重复配置、issue 提供方设置、插件用户数据，以及两层归档（近期与旧）。它不是每个本地数据库的逐字节副本。

设备本地的支持性数据被有意排除在该快照之外。示例包括同步冲突日志、设备本地的崩溃安全编辑器草稿（localStorage `SUP_LOCAL_DRAFT_*`）、操作日志传输元数据、内部导入恢复槽、Local REST API 访问令牌（`local-rest-api-token`），以及存储在单独的 `sup-sync` 凭据数据库中的同步提供方私有配置（凭据与加密密钥材料）。相反，应用模型内的 issue 提供方设置可能包含 API 凭据或令牌。

普通备份与导出文件是**明文 JSON**，即使已启用同步加密也是如此。请将其视为敏感数据：像保护其中可能包含的工作数据与凭据一样保护它们。匿名/隐私导出会遮蔽已知字段名，但它不是凭据安全边界：分享前请检查并移除任何残留的提供方或插件凭据、令牌与私密内容。

## 用户数据文件夹的用途

用户数据文件夹是桌面应用存储以下内容的应用数据目录：

- 全部用户数据、设置与配置
- 自动备份
- 自定义主题文件（`styles.css`）
- Local REST API 访问令牌（`local-rest-api-token`）
- IndexedDB 与 localStorage 数据（由 Electron 管理）

## 各平台默认位置

| 平台        | 位置                                                                                              |
| ----------- | ------------------------------------------------------------------------------------------------- |
| **macOS**   | `~/Library/Application Support/superProductivity/`                                                |
| **Windows** | `C:\Users\<YOUR_USER_NAME>\AppData\Roaming\superProductivity/` 或 `%APPDATA%\superProductivity` |
| **Linux**   | `~/.config/superProductivity/`                                                                    |

备份路径显示在界面 Settings → Automatic Backups 下（含 `backups/` 子文件夹），并在从命令行启动应用时打印。

### 自定义文件夹位置

你可以使用 `--user-data-dir` 命令行参数指定自定义用户数据目录：

```bash
superproductivity --user-data-dir=/path/to/my/data
```

末尾斜杠会被去掉。该会话会使用自定义路径而非默认路径。

### Snap 包（Linux）

在 Linux 的 Snap 包上，应用使用 `SNAP_USER_COMMON` 目录，以免数据被 Snap 更新过程访问。有效路径为 `$SNAP_USER_COMMON/.config/superProductivity`（或等效的应用名路径）。

### Flatpak 包（Linux）

Flatpak 将数据保存在包沙箱内。应用此处不设置自定义路径；Flatpak 将 `XDG_CONFIG_HOME` 重定向到沙箱，因此有效路径为 `~/.var/app/com.super_productivity.SuperProductivity/config/superProductivity/`。确切位置显示在 Settings → Automatic Backups。

沙箱带来两个后果：

- 第二个非 Flatpak 安装（AppImage、`.deb`、Snap）会读取不同目录，**不会**看到这些数据。在打包格式之间迁移请通过导出/导入，而不是并排安装。
- 沙箱**之外**的同步或备份目标需要显式文件系统权限，可通过 [Flatseal](https://flathub.org/apps/com.github.tchx84.Flatseal) 或 `flatpak override` 授予。没有权限时应用会报告权限错误；`~/.var/app/` 内的路径始终可用。

### Windows Store

Windows Store 构建可能使用不同路径，其中包含 Windows Store 包标识符（在 `Local\Packages\...\LocalCache\Roaming` 下，而非 `Roaming`）。这取决于 Windows 是否对该包进行虚拟化：虚拟化包的 `AppData` 写入会重定向到 `LocalCache`，而完全信任包则写入普通的 `Roaming` 路径。Settings 会显示你机器上实际存在的位置，因此请在那里查看，而不要假定某一种。

## 目录结构

### backups/ 子目录

- 存储自动备份文件（JSON）。
- 位置：`{userData}/backups/`。
- 在桌面上，自动备份文件使用文件名格式 `YYYY-MM-DD_HHmmss.json`。

### styles.css（可选）

- 用于桌面样式的自定义主题文件。
- 必须由用户手动创建，并直接放在用户数据文件夹中（不要放在子文件夹中）。
- 由主进程加载并注入渲染进程；无效 CSS 可能无法加载并会记入日志。

### local-rest-api-token（可选）

- 首次启用 Local REST API（见 [[3.01-API]]）时直接在用户数据文件夹中创建。在 macOS 与 Linux 上以模式 `0600`（仅所有者可读写）写入；在 Windows 上继承文件夹的 ACL。
- 以明文包含 API 访问令牌——这是凭据，不是设置。它是**按设备**的：不属于应用状态，因此从不同步；从备份或导入恢复的设备会保留（或生成）自己的令牌。
- **不包含**在自动备份、手动备份、“Export data” 或导入中——那些只携带应用状态。导入另一设备数据的设备仍使用自己的令牌，现有脚本可继续使用 **Settings → Misc → Access Token** 中显示的令牌。
- **会**包含在整个用户数据文件夹的冷拷贝中（文件级配置备份、磁盘镜像、文件夹同步）。此类副本因此包含有效的 API 凭据：请像对待配置本身一样保持私密，或之后从 Settings → Misc 重新生成令牌。
- 删除该文件是安全的：下次启用 API——或在设置中读取令牌——时会生成新令牌。持有旧令牌的脚本随后会收到 `401`。

### IndexedDB 与 localStorage（由 Electron 管理）

- IndexedDB 数据库与 localStorage 条目位于 userData 路径下的平台特定位置。
- 由 Electron 管理；请勿手动移动或编辑这些文件。

## 文件类型与格式

### JSON 备份文件

- **格式：** 桌面自动备份为 `YYYY-MM-DD_HHmmss.json`。
- **内容：** 以明文 JSON 序列化的可恢复应用模型快照。
- **命名：** 按本地日期与时间加时间戳（例如 `2025-01-15_143022.json`）。

### CSS 主题文件

- **文件：** `styles.css`（必须使用确切名称）。
- **用途：** 用于主题的自定义 CSS；由用户创建且可选。

### IndexedDB 数据库

- **SUP_OPS：** 运行时快照、保留的操作、因果元数据、归档与内部恢复状态的操作日志持久化。可执行的 schema 与升级所有者为 `src/app/op-log/persistence/op-log-db-schema.ts` 与 `src/app/op-log/persistence/db-upgrade.ts`；访问由 `OperationLogStoreService` 及其持久化适配器拥有。
- **pf：** 用于迁移与恢复的旧数据库。
- **sup-sync：** 设备本地的同步提供方凭据、私有配置与加密密钥材料，由 `src/app/op-log/sync-providers/credential-store.service.ts` 拥有。该数据库不属于应用模型备份或导出。
- **SUPPluginCache：** 插件缓存。
- **SUP_CONFLICT_JOURNAL**（version 1）：`/sync-conflicts` 下同步冲突审阅条目的设备本地存储。存储与审阅 UI 存在，但当前生产环境的远程冲突处理已禁用日志写入，因此日志处于休眠/不完整状态，不是完整的解决记录。现有条目有意与 `SUP_OPS` 分开，**从不同步或上传**（它们可能原样捕获冲突中被丢弃的一侧），修剪为 14 天 / 最新 200 条——在应用启动时，以及会话中存储超过软上限 220 条时——并在完整数据集被替换时清除（备份导入/恢复、配置切换）。

### localStorage 键

UI 与应用状态使用如下键存储：

- `SUP_UI_HELPER`、`SUP_ACTION_LOG`、`SUP_LAST_ERROR_ACTION_LOG`
- `SUP_IS_PROJECT_LIST_EXPANDED`、`SUP_IS_TAG_LIST_EXPANDED`
- `DARK_MODE`、`SUP_NAV_SIDEBAR_EXPANDED`、`SUP_NAV_SIDEBAR_WIDTH`、`SUP_RIGHT_PANEL_WIDTH`
- `SUP_IS_ADD_TO_BOTTOM` 及其他（完整集合见 `storage-keys.const.ts`）。
- `SUP_LOCAL_DRAFT_*`：设备本地的**崩溃安全编辑器草稿**，每个进行中的编辑一条，键为 `SUP_LOCAL_DRAFT_${profileId}:${entityType}:${entityId}`。它们支撑全屏备注编辑器，使未保存编辑在崩溃或强制关闭后仍可保留，并且**从不同步或上传**，也**排除在备份与导出之外**——草稿是瞬时设备状态，不是应用数据。草稿在冗余时立即移除：编辑保存或丢弃时、本设备上删除备注时，以及活动配置的数据集被整批替换时（JSON 导入、SuperSync 恢复）。删除某配置时也会删除该配置的草稿；切换配置会保留各配置的草稿。从未重新打开其备注的崩溃残留会在应用启动时修剪，超过 14 天的会被清除。

## 备份行为

**自动备份：** 在设置中启用后，应用按计划创建备份（默认：每 5 分钟）。间隔与备份子目录无法在 UI 中配置。存储位置取决于平台：

| 平台                   | 自动备份存储位置                                                                                                                                                                              |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Electron（桌面）**   | `{userData}/backups/` 中带时间戳的 JSON 文件（`YYYY-MM-DD_HHmmss.json`）                                                                                                                      |
| **Android**            | 原生应用私有 SQLite 存储（`SupKeyValStore`，键 `backup` / `backup_prev` 分别表示最新与上一个槽位），与 WebView IndexedDB 分开，以便在 IndexedDB 被驱逐后仍能保留                               |
| **iOS**                | Capacitor Filesystem API：`Directory.Data` 中最新与上一个 JSON 文件                                                                                                                           |
| **Web**                | 无自动文件备份；使用 “Export data” 手动下载文件                                                                                                                                               |

在桌面上，**Maximum backup files** 设置会限制 `backups/` 文件夹中保留的带时间戳自动备份文件数量。超过上限时会删除较旧文件。在默认上限下，清理会保留最近 30 个备份文件，外加当前日与前 20 天中每天最多一个最新备份（若那些天有文件）。由于每日备份常与最近 30 个文件重叠，实际文件数可能更少。

在移动端（Android/iOS），若应用启动时没有本地数据但存在可用的设备上备份——典型情况是“系统驱逐 WebView 存储后出现空白应用”——则最新可用备份会在**启动时自动恢复**，无需提示，并以 snackbar 报告恢复了多少任务与项目。仅在实时存储确实为空时发生；应用内故意“删除全部数据”会留下有效（空）状态，不会自动恢复。**Restore latest automatic backup** 仍可在 Settings -> Sync & Backup -> Automatic Backups 中手动使用，该处显示 **Last backup** 时间戳以便确认你受保护；手动恢复会在确认后替换当前本地数据。若已配置同步，恢复的数据（自动或手动）会视为备份导入：下次同步时会传播到并覆盖你的其他已同步设备，因此应将其作为恢复操作而非日常操作。

**手动备份：** (1) Settings → Sync & Export 中的 **Create manual backup** 使用与自动备份相同的机制创建备份（位置因平台而异）。(2) **Safety backups** 在某些同步操作前自动创建；应用保留有限数量的槽位（例如最近两个、今天第一个、昨天第一个）。(3) **Export data** 将完整应用模型快照以 JSON 下载到你选择的路径（或 Web 上的浏览器下载文件夹）。

**包含内容：** 备份与导出包含上述可恢复应用模型，在请求归档时包括两层归档。它们不复制保留的操作日志、因果/传输元数据、设备本地冲突日志、设备本地崩溃安全编辑器草稿（localStorage `SUP_LOCAL_DRAFT_*`）、内部导入恢复槽、单独存储的同步提供方凭据与加密密钥材料，或 Local REST API 访问令牌（`local-rest-api-token`）——见上文。单独的单槽 **import backup** 本地存储在 IndexedDB（`import_backup`）中。应用在通过文件导入或同步冲突操作 **Use Server Data** 替换本地状态之前捕获它。成功的 Use Server Data 替换会显示持久的 **Undo** 操作以恢复该备份；中断的替换在同步恢复时提供相同的恢复操作。只要该备份仍在，应用重新加载后 Undo 仍可用。该槽位是内部恢复状态，不包含在导出或用户可见的自动/手动备份列表中。

应用模型快照仍可能包含私密工作内容与 issue 提供方 API 凭据或令牌。其 JSON 序列化不受同步加密保护；请保护普通备份/导出文件。匿名/隐私导出属于尽力而为，因此在用于诊断分享前请检查并移除任何残留凭据、令牌或私密内容。

## 导入与导出

**导出：** 导出会生成导出时刻当前状态的**快照**。文件为明文 JSON，包含（或包装）可恢复的应用模型状态。关系通过 ID 引用保留（例如任务引用 `projectId` 与 `tagIds`；子任务引用 `parentId`）。导出可通过 Settings → Sync & Export → Import/Export（例如 “Export data” / 下载备份）使用。

**导入：** 应用接受相同格式的**完整备份**（完整应用模型状态，可选地带有时间戳与版本包装）。支持的结构：(1) 原始完整状态对象，或 (2) 带有 `data`、`timestamp` 与 `crossModelVersion` 的包装对象，其中 `data` 为完整状态。旧版 V1 格式（例如 `config` + `tasks` 数组）会被检测但**不再支持**；会向用户显示不支持迁移的提示。在应用导入之前，应用会**验证**数据（结构与跨实体关系）。若验证失败，在可能时可能运行**自动修复**（例如修复孤立任务、无效的项目/标签引用、缺失的归档结构）。若快照记录的同步加密状态与当前应用不同，应用可能在导入前显示**确认对话框**。该警告关乎导入状态将如何配置后续同步；并不表示备份文件本身已加密。导入后，当前状态被替换；归档数据写入 IndexedDB。如何执行恢复见 [[2.02-Restore-Data-From-Backup]]。

## 同步

**策略：** 应用是本地优先的，将变更记录为操作，再将该日志适配到不同传输方式。**SuperSync** 通过有序的服务器 API 发送操作。文件提供方使用默认的 **v2** 单体格式，在携带操作的上传中重建并上传当前快照、两层归档以及保留的操作。可选的 **v3** 拆分格式将这些部分分开存储，因此普通操作上传不会在压缩之间重写快照。见维护者现场指南中的 [transport comparison](../sync-and-op-log/sync-architecture.html#transport)。

**冲突解决：** 使用向量时钟检测冲突（同一实体在两处并发变更）。解决时首先应用明确的归档/删除优先级与安全的不相交字段合并。其余重叠使用**最后写入获胜（LWW）**：较新的操作时间戳获胜；完全平局则使用稳定的 client-ID 排序。当本地或合并结果必须主导两边历史时，应用会为下次上传发出相应的 update、archive-win 或 delete-win 操作。**完全相同的冲突**会自动解决，无需用户操作。在**首次同步**且本地与远程均已有数据的情况下，应用可能显示对话框让你选择 **use local** 或 **use remote**。解决后，状态会按需验证与修复。

## 用户可编辑 vs 系统管理

**用户可编辑：**

- **styles.css** — 创建并编辑以使用自定义主题。
- **备份文件** — 可通过 Settings → Sync & Export → Import/Export → Import from file 恢复（见 [[2.02-Restore-Data-From-Backup]]）。

**系统管理（请勿手动编辑）：**

- IndexedDB 数据库。
- localStorage 条目。
- 活动备份文件（可作为 JSON 读取，但不建议手动编辑）。

## 大小限制与配额

### 客户端 IndexedDB

- 发生 `QuotaExceededError` 时，应用触发紧急压缩（保留 24 小时而非 7 天），并使用断路器避免无限重试。
- 适用浏览器/操作系统配额与可用磁盘空间。

### SuperSync 服务器（若使用；beta）

- 默认配额：每用户 100 MB。
- 超出配额时自动清理。

## 权限

- 应用需要对用户数据文件夹的正常读写访问。默认位置在用户主目录或应用数据目录下；不需要管理员/root 权限。
- 需要原生文件系统或进程访问的插件需要
  `nodeExecution` 权限，并在 Electron 桌面应用中获得明确同意。
  内置与上传/社区插件均可请求该权限。上传的插件在原生提示中
  标识为未验证的第三方代码；授予访问权限后，该插件可以你的用户
  账户相同的机器访问权限运行代码。见 [[2.21-Manage-Plugins]]。

## 恢复与修复

### 自动数据修复

- 验证在操作生命周期的多个点运行。
- 修复孤立任务、无效引用与不一致关系等问题；为日志创建 `REPAIR` 操作。

### 灾难恢复

- 若主数据库（`SUP_OPS`）缺失或损坏，应用尝试从旧版 `pf` 数据库加载并运行 genesis 迁移。
- 若恢复失败，需要完整重新同步（或从备份恢复）。
- 若迁移旧版 `pf` 数据库失败，迁移对话框会报告错误并等待。它还提供 **Continue without old data**，以空存储启动应用，而不是每次重启都卡在错误上。不会删除任何内容：`pf` 数据库留在磁盘上，仅获得 `_migration_skipped` 标记，因此迁移与恢复不再选取它。然后可正常导入自动的迁移前备份，未改动的 `pf` 数据库仍可作为手动恢复的第二份副本。

### 备份恢复

- 通过 Settings → Sync & Export → Import/Export → Import from file 从 `backups/` 中的备份文件恢复。见 [[2.02-Restore-Data-From-Backup]]。

### 同步状态损坏

- 当已同步操作无法干净应用时，应用会标记同步状态并重新验证；完整重新同步可恢复一致状态。

## 配置与版本控制

- 公共应用配置是 `SUP_OPS` 中模型快照的一部分；本地 UI 设置也使用 localStorage（`SUP_*` 及相关键）。同步提供方私有配置与密钥材料单独存放在 `sup-sync` 凭据数据库中。
- **数据库 schema：** 将 `src/app/op-log/persistence/op-log-db-schema.ts` 与 `src/app/op-log/persistence/db-upgrade.ts` 视为可执行的真实来源；不要依赖文档中复制的版本号或存储清单。
- **应用版本：** 在构建中定义（例如 `src/environments/versions.ts`），不存储在用户数据文件夹中。
- **备份文件：** 每个 JSON 文件携带可恢复的应用模型快照；桌面自动备份命名包含日期与时间。

## 应用访问（桌面）

- **主进程：** 路径通过 Electron `app.getPath('userData')` 获取；使用 `--user-data-dir` 或 Snap 逻辑时用 `app.setPath('userData', path)` 设置自定义路径。
- **渲染进程：** 路径通过 IPC 暴露（例如 `getUserDataPath()`）。
- **备份与文件同步：** 使用 Node.js `fs` API（例如 `readFileSync`、`writeFileSync`、`readdirSync`、`statSync`、`unlinkSync`）进行备份与本地文件同步。

## 备注

- **Web 应用：** 数据仅存在于浏览器存储；没有用户数据文件夹。见 [[3.05-Web-App-vs-Desktop]]。
- **不要实时同步此文件夹：** 通用 WebDAV 或云文件夹工具可能在 Electron 的 IndexedDB/LevelDB 文件与锁文件变化时复制它们，有导致配置损坏或不可用的风险，同时还会上传明文备份与设备本地凭据。多设备请使用 Super Productivity 内置同步。冷配置备份时，请先完全关闭应用，将该文件夹作为敏感备份整体复制，并仅在应用关闭时恢复。
- **主题：** 示例主题与主题创建指南：[super-productivity-themes](https://github.com/super-productivity/super-productivity-themes)。
