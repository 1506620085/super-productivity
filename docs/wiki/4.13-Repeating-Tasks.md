# 重复任务

Super Productivity 中的重复任务会按计划循环出现——每日、每周、每月或每年——这样你就不必一遍遍创建同一任务。应用会保存一份**重复配置**来定义规律，并在到期时自动创建新的任务实例。了解重复任务如何定义、下一实例何时创建，以及应用如何避免重复并处理跳过日期，有助于你在 Planner、Schedule 和 Today View 中可靠地使用它们。

关于如何在界面中创建、编辑和管理重复任务，请参阅 [[2.06-Manage-Repeating-Tasks]]。关于重复配置如何融入任务模型，请参阅 [[4.09-Task-Attributes]]。重复任务不能变成子任务；请参阅 [[4.11-Subtasks]]。

## 重复任务如何定义与存储

重复任务由与任务关联的**重复配置**定义。该配置单独存储，并描述重复规律。你可以设置的关键选项包括：

- **重复周期** — 任务多久重复一次：每日、每周、每月或每年。
- **重复间隔** — 实例之间相隔多少单位（例如「每 2 周」或「每 3 个月」）。
- **开始日期** — 规律从何时开始；应用不会在此日期之前创建实例。
- **上次创建的实例** — 应用会跟踪最近一次已创建任务实例的日期，以便知道接下来该创建什么。
- **跳过日期** — 你可以将特定日期标记为「跳过」，这样那些天不会创建实例；规律在其前后继续。这样你可以跳过假期、休息日或一次性例外，而无需改动规则。
- **开始时间与提醒** — 可选：为每个实例设置默认时间（及提醒），使重复工作在 Schedule 上以固定时间出现。
- **子任务模板** — 可选：一套会添加到每个新实例的子任务，这样就不必每次都重建相同清单。

应用还提供映射到常见规律的**快捷设置**——例如「每天」「每周的这一天」「每月的这一日」「仅工作日」（周一至周五）、「每年的这一日」，或用于完全自定义的「自定义」。这些快捷方式会填入底层的周期、间隔，以及（对每周而言）哪些工作日。

当你把任务设为可重复时，它会保留项目、标签及其他属性；会添加重复配置，并由应用用其生成未来实例。

## 什么会触发下一实例的创建

当应用检测到某个实例已到期且尚不存在时，会创建**下一个任务实例**。具体做法是：

1. **查看规律** — 根据重复配置（周期、间隔、开始日期、上次创建的实例），应用从今天（或所选的「截至」日期）向前倒推，算出最近一次*应当*已创建任务的日期。由此确定哪些日期「缺失」并需要实例。
2. **检查每个候选日期** — 对每个这样的日期，应用会确认该日期尚无实例（且该日期不在你的跳过日期列表中）。若实例缺失，则创建。
3. **更新配置** — 创建实例后，应用会更新「上次创建的实例」，以免为同一日期再创建一次。这样可保持规律同步并避免重复。

当你**首次**将任务设为可重复时，应用会根据规律和开始日期计算**首次出现**日期。它可能将该任务的截止日期设为该首次出现；若首次出现不是今天，还可能把任务从 Today 列表中移除，使其出现在正确的那天。这样第一个实例从一开始就与重复规则对齐。

实例创建会作为正常使用应用的一部分运行（例如打开应用或切换上下文时），因此逾期实例会在应用赶上时创建。除非你的工作流暴露了「创建下一实例」操作，否则你不必手动触发创建。

## 应用如何防止重复并处理例外

应用使用多种机制，避免你得到重复实例，并确保同步与跳过日期行为正确。

### 确定性任务 ID

每个重复实例都以由重复配置和日期推导出的**可预测 ID** 创建。这意味着同一配置和同一日期在每台设备上都会产生相同的任务 ID。当你同步时（例如通过 WebDAV 或 Dropbox），两台都运行「为此日期创建实例」逻辑的设备会创建相同 ID 的任务，同步因此看到一个任务而非两个。这可防止跨设备重复。

### 创建前的重复检查

在为给定日期创建实例之前，应用会：

1. **检查是否已有实例** — 查找具有预期确定性 ID、或以该日期为截止日期的任务。若已存在（例如在另一设备上创建并已同步，或带有不同 ID 但同一日期的旧「遗留」任务），则不再创建。这同时覆盖新数据和遗留数据。
2. **检查跳过日期** — 若该日期在你的已跳过（已删除）实例列表中，应用不会为该日期创建任务。规律继续；该日期只是被省略。
3. **更新「上次创建」** — 成功创建后，应用会更新配置中的「上次创建的实例」，以便下次运行知道不要再为该日期创建。

这些步骤合在一起，可保证每个重复配置在每个日期最多只有一个实例——无论是本地还是同步之后。

### 跳过日期（例外）

你可以在不改动重复规则的情况下**跳过特定出现**。这些日期存储在配置的例外列表中。应用绝不会为这些日期创建实例，但会为所有其他匹配规律的日期创建实例。因此你可以跳过一天（或几天），其余日程保持不变。

## Schedule 与 Planner 中的重复任务

**Schedule** 视图可以显示重复任务的**预估**实例（若设置了开始时间），即使实际任务实例尚未创建。这为你提供前瞻式时间线：你能看到下一次「站会」或「复盘」按规律将在何时发生。实例一旦创建，就会作为普通任务出现在 Schedule 上。请参阅 [[4.04-Schedule-View]]。

**Planner** 视图也会在重复任务将出现的日子上显示预估投影，便于你看清重复工作如何融入一周或一个月。请参阅 [[4.03-Planner-View]]。

重复规律的日期计算在内部使用一致的参考时间（正午），以避免时区与夏令时问题，因此「下一次出现」在跨时区和 DST 变更时仍保持正确。

## 小结

- 重复任务由**重复配置**定义（周期、间隔、开始日期、跳过日期，以及可选的时间与子任务模板）。
- 当应用检测到到期日期尚无实例时，会**创建下一实例**，然后更新「上次创建」以免重复。
- **确定性 ID**（配置 + 日期）可在跨设备同步时防止重复实例。
- **跳过日期**让你省略特定出现而不破坏规律。
- **Schedule**（以及 Planner）可显示预估的重复实例；实际实例在创建后出现。

## 「等待完成」选项

当你在重复任务上启用**「Wait for completion」（等待完成）**时，应用在你完成当前实例之前不会创建下一实例。这对必须按序完成的任务很有用——例如，只有在完成上周复盘后才应出现的每周复盘，或不希望落后时堆积的重复杂务。

### 工作原理

- **正常行为**：应用按日程创建下一实例（例如每周一），无论你是否完成了上一实例。
- **启用「Wait for completion」时**：应用会检查是否存在任何未完成的实例（包括已归档任务）。若存在，则不会创建下一实例。一旦你将当前实例标为完成，若下一计划出现已到期，下一到期实例会立即出现。

### 关键行为

- **完成后立即创建**：当你完成作为门控的任务，且下一计划出现已到期时，下一实例会马上创建——你不必等到第二天或重启应用。
- **已归档实例也计入**：若你归档未完成的实例，它仍会阻止创建下一实例。这可防止在旧工作未完成时规律继续推进。
- **已完成的阻塞会重新检查**：完成任何未完成的现用或已归档实例后，会重新检查是否可创建下一到期任务。若仍有其他未完成实例，创建仍保持阻塞。

### 使用场景

- **顺序复盘**：只有在完成上一份后才应出现的每周或每月复盘
- **不应堆积的杂务**：希望先完成一个再出现下一个的重复维护任务
- **习惯追踪**：希望确保完成后再进入下一次出现的任务

此选项独立于「从完成日期重复」（后者会将日程重新锚定到完成日）。若希望任务在完成后 N 天再重复，*并且*在创建下一实例前等待完成，可以两者都启用。

## 「勿让逾期实例堆积」选项

当你在重复任务上启用**「Don't let overdue instances pile up」（勿让逾期实例堆积）**时，错过的出现不会积累成一堆重复的逾期任务——你只会保留一个保持最新的实例。一旦已有更新的实例，空的错过实例会被移除；凡是你跟踪过时间、完成过子任务，或编辑过任务本身（标题、备注、估算、标签、附件、截止日期、项目、子任务或计划时间）的实例则始终保留。提醒不算作编辑——已触发、已关闭或已延后的提醒仍使该实例符合清理条件，因为应用会自行改写该字段。因此延后逾期实例并不会保留它：延后的提醒会随实例一起消失，由当前实例继续承载任务。

### 默认行为

- **「每天」预设默认开启**（或等效的自定义「每一天」周期）。日常任务是唯一会真正堆积的日程（若落后，每天一个空的逾期副本），且今天始终是计划日，因此错过的实例会在同一天可靠地回来——绝不会悄悄消失。你得到的是一个当前实例，而不是不断增长的堆叠。
- **其他所有日程默认关闭**（工作日、每周、每月、每年，以及长于一天的自定义周期）。这些最多只有一次错过，因此不会堆积——而且逾期的「每月 1 日付房租」或「续订域名」应作为提醒保持可见，而不是安静消失直到下一次出现。

这只设定新创建重复任务的**默认值**。现有任务保留其原有配置，你可在重复对话框的 **Advanced（高级）** 部分为任意任务打开或关闭该选项。

### 何时使用

- **日常习惯与例行**：浇花、每日站会、收件箱清零——跳过陈旧重复带来的愧疚堆，只看今天的。
- **账单与续订请保持关闭**：对每月或每年的义务保持关闭（默认），这样错过的那次会留在列表中，直到你处理完毕。
