# 管理你的数据

Super Productivity 中的“你的数据”是指应用为表示你的工作而存储的一切：任务（活动与已归档）、项目、标签、时间跟踪、指标、备注、提醒、配置等。应用是**本地优先（local-first）**的：数据保存在你的设备（或浏览器）上，由你控制如何备份、导出、导入与同步。了解“你的数据”包含什么、导入与导出如何工作、备份如何创建，以及同步与冲突如何处理，有助于你保障数据安全，并在设备间迁移或从问题中恢复。

关于数据存储位置、各平台备份去向，以及备份/导入/导出/同步的技术细节，见 [[3.06-User-Data]]。关于如何从备份文件恢复，见 [[2.02-Restore-Data-From-Backup]]。

## 你的数据包含什么

完整备份或导出是应用模型的**可恢复快照**。它包括：

- **任务** — 活动任务与已归档任务（近期与旧归档），含全部属性与时间跟踪数据。
- **项目与标签** — 全部项目、标签及其设置。
- **时间跟踪** — 每项任务每日已用时间、休息时间及相关状态。
- **配置** — 全局设置、提醒、专注模式与休息提醒选项等。
- **备注** — 任务备注与项目备注。
- **指标** — 每日指标、反思、影响与能量评分、专注会话。
- **其他** — 简单计数器、规划器与看板状态、任务重复配置、issue 提供方设置、插件数据，以及归档（新与旧）。

这是恢复工作区所需的状态，而非每个本地数据库的逐字节副本。设备本地的支持性数据被有意排除在外，包括同步冲突日志、操作日志传输元数据、内部导入恢复槽，以及单独存储的同步提供方私有配置（凭据与加密密钥材料）。快照内的 issue 提供方设置仍可能包含 API 凭据或令牌。

普通备份与导出文件是**明文 JSON**，即使已启用同步加密也是如此。请像对待其中可能包含的私密工作数据与凭据一样保护它们。匿名/隐私导出会遮蔽已知字段名，但它不是凭据安全边界：分享前请检查并移除任何残留的提供方或插件凭据、令牌与私密内容。

## 导入：把数据带入

**导入**会用备份或导出文件中的数据替换当前应用数据。应用支持**完整备份格式**：单个 JSON 结构，包含（或包装）完整的应用模型状态。v10–v13 数据形态下的 pre-v14 备份会被检测并在验证前迁移。更早的 V1 `config` + `tasks` 格式会被检测到但不再支持，因此会显示不支持迁移的消息。

**验证与修复：** 在应用导入之前，应用会**验证**数据（结构与关系，例如任务是否引用已有项目与标签）。若验证失败，在可能时仍可能**自动修复**数据——例如修复孤立任务、缺失的项目或标签引用，或不一致的列表——从而使你得到一致状态而非失败的导入。若无法修复，导入会中止并报错。

**加密：** 若快照记录的同步加密状态与当前应用不同，应用可能在导入前警告你，因为导入的状态可能改变后续同步的配置方式。这**并不**表示备份文件本身已加密；普通备份与导出 JSON 仍为明文。

**导入的效果：** 导入会**替换**当前状态。应用会持久化导入的数据（包括将归档数据写入存储），并将其视为新的真实来源。你之前的状态不再有效；若有旧备份，只能通过导入该备份来恢复。

## 导出：拍摄快照

**导出**会生成你在导出时刻数据的**快照**。它不是“实时”视图：那一刻的应用模型（若你选择包含归档，则包括归档）被序列化为一个明文 JSON 文件。你可将该文件用作备份、移到另一设备或归档保存，但应安全地存储与传输。关系（例如任务 → 项目、任务 → 标签、子任务 → 父任务）通过 JSON 中的 **ID 引用**保留；导入时使用的验证与修复逻辑确保该文件稍后导入时这些引用保持一致。

因此，导出 = “按当前可恢复应用模型保存”；导入 = “从该文件加载该模型并替换当前数据”。

## 备份：自动与手动

**自动备份** — 在设置中启用后，应用会按计划创建备份（例如每 5 分钟）。存储位置取决于平台：在**桌面（Electron）**上，备份是用户数据文件夹中带时间戳的 JSON 文件（例如 `backups/` 目录），并会自动清理较旧文件；桌面的 **Maximum backup files** 设置控制保留多少个自动备份文件。在 **Android** 与 **iOS** 上，备份存储在平台私有存储中。在 **Web** 上没有基于文件的自动备份；你使用 “Export data” 下载文件。各平台确切位置与行为见 [[3.06-User-Data]]。

**手动备份** — 你可通过以下方式触发备份：(1) 在设置中使用 **“Create manual backup”**，(2) 依赖应用在某些同步操作前创建的 **safety backups**（应用保留有限数量的近期与每日槽位），或 (3) 使用 **“Export data”** 下载备份文件。导出的文件稍后可通过 Settings → Import/Export 导入（见 [[2.02-Restore-Data-From-Backup]]）。

**包含内容：** 备份与导出包含可恢复的应用模型；当请求归档时，会包含近期与旧归档两层。设备本地的操作元数据、冲突审阅历史、内部恢复状态，以及单独存储的同步凭据/密钥材料不会被复制。文件仍可能包含私密工作内容与 issue 提供方凭据，且为明文 JSON。匿名/隐私导出属于尽力而为，因此在用于诊断分享前请检查并移除任何残留凭据、令牌或私密内容。

## 同步：本地优先与冲突解决

应用是**本地优先**的，将变更记录为操作，再将该日志适配到不同传输方式。**SuperSync** 通过有序的服务器 API 发送操作。文件提供方使用默认的 **v2** 单体格式，在携带操作的上传中重建并上传当前快照、两层归档以及保留的操作。可选的 **v3** 拆分格式将这些部分分开存储，因此普通操作上传不会在压缩之间重写快照。见维护者现场指南中的 [transport comparison](../sync-and-op-log/sync-architecture.html#transport)。

**冲突** — 当同一数据在两处（例如两台设备）变更后才同步时，应用比较向量时钟以检测并发。解决时首先应用明确的归档/删除优先级与安全的不相交字段合并。其余重叠使用**最后写入获胜（last-write-wins）**：较新的操作时间戳获胜；完全平局则使用稳定的 client-ID 排序。当本地或合并结果必须主导两边历史时，应用会发出相应的 update、archive-win 或 delete-win 操作以便结果传播。在某些情况下（例如首次同步且本地与远程均已有数据），应用可能要求你选择 **use local** 或 **use remote**。解决后，应用会验证并可修复状态，以使引用保持一致。

**不相交字段自动合并** — 对于同步契约明确支持重建的实体类型，对不同真实字段的编辑可以合并，而不是丢弃一方。仅在明确安全且任一方都不是删除或结构性变更时才会发生；不受支持或重叠的变更会回退到 last-write-wins。

**审阅自动解决的内容** — 设备本地的 **conflict journal** 存储与 **Sync Conflicts** 页面（`/sync-conflicts`，也可从 Settings → Sync 链接）存在，但当前生产环境的远程冲突处理已禁用日志写入。因此该页面处于休眠/不完整状态：并非每次自动解决都会被记录或可供审阅。对于确实存在的条目，你可以看到哪一侧获胜、哪些字段不同及双方取值，然后选择 **Keep**（确认自动解决）或 **Flip**（将丢弃的变更作为新编辑重新应用并同步到所有设备——不会回退历史）。在无法安全重新应用处（例如被覆盖的删除或结构性移动）Flip 不可用。现有日志数据仅供参考：它保存在设备上，从不同步上传，不属于备份/导出，在你导入备份或切换用户配置时会被清除，旧条目会自动修剪（超过 14 天或超出最新 200 条）。

因此实践中：先明确归档/删除规则，在安全字段不重叠时两边变更都保留，其余重叠再按确定性的较新者获胜。仅在应用提示时（例如首次同步）你才需要选择。Sync Conflicts 页面可能包含较早的审阅条目，但当前生产环境的日志写入已禁用，因此它不是完整的解决历史。

## 摘要

- **你的数据** = 可恢复的应用模型（任务、项目、标签、时间、配置、备注、指标、归档等）；设备本地支持性存储是分开的。
- **导入** = 用备份文件替换当前数据；在可能时验证并修复；可能就同步加密状态变更发出警告。
- **导出** = 导出时刻的明文 JSON 快照；请妥善保护。匿名/隐私导出在用于诊断分享前仍需检查凭据、令牌与私密内容。
- **备份** = 自动（启用时，位置因平台而异）与手动（手动按钮、safety backups、导出）。
- **同步** = 由 per-operation 的 SuperSync 传输或文件格式承载的本地操作日志；冲突使用明确优先级、安全的不相交合并，必要时再使用确定性的较新者获胜。
