# 配置开发环境

如何为开发与构建配置环境变量及生成的配置文件。

应用使用静态环境文件存放标志（dev/prod/stage），并用 `.env` 文件存放密钥与动态值。`.env` 中的值会转换为 TypeScript 常量，因此你使用类型安全的导入，而非 `process.env`。

## 一次性设置

```bash
cp .env.example .env
```

编辑 `.env` 并添加所需的密钥（例如可选集成的 API 密钥）。不要提交 `.env`；生成的文件 `src/app/config/env.generated.ts` 已被 gitignore。

## 在代码中使用变量

```typescript
import { ENV } from './app/config/env.generated';

const value = ENV.SOME_KEY;
```

或使用辅助函数：

```typescript
import { getEnv, getEnvOrDefault } from './app/util/env';

const value = getEnv('SOME_KEY');
const withDefault = getEnvOrDefault('SOME_KEY', 'default');
```

类型与键在运行任何构建或 serve 命令时从 `.env` 派生。

## 添加新变量

1. 在 `.env` 中添加键和值。
2. 运行 `ng serve` 或构建命令，以便重新生成 `env.generated.ts`。
3. 在代码中使用 `ENV.NEW_KEY` 或 `getEnv('NEW_KEY')`。

## 静态配置与动态配置

- **静态**：`src/environments/environment.ts`、`environment.prod.ts`、`environment.stage.ts`（生产/预发标志、版本）。
- **动态**：`.env` → `src/app/config/env.generated.ts`（密钥与每位开发者的值）。

## 单元测试浏览器（Chrome）

单元测试通过 Karma 在无头 Chrome 中运行（`npm test`、`npm run test:file`）。`pre-push` git 钩子会运行 `npm run lint && npm run test`，因此 **必须能解析到 Chrome 二进制文件，否则 `git push` 会失败**，并出现以下错误：

```text
ERROR [launcher]: No binary for Chrome browser on your platform.
  Please, set "CHROME_BIN" env variable.
```

Karma 的 `karma-chrome-launcher` 通过 `CHROME_BIN` 环境变量定位浏览器，若未设置则回退到系统安装的 Chrome。你可以采取以下两种方式：

### 方式 A — 使用系统 Google Chrome

通过操作系统的包管理器安装 **Google Chrome**。Karma 配置使用 `karma-chrome-launcher` 的 `Chrome` 启动器（`src/karma.conf.js` 中的 `base: 'Chrome'`），在 Linux 上它只会自动检测真正的 Google Chrome —— 探测 `google-chrome` / `google-chrome-stable`，**不会**探测 `chromium` / `chromium-browser`。因此发行版的 **Chromium** 包通常不会被自动识别；对于非 Google Chrome（或安装在非标准位置的 Chrome），请按方式 B 显式设置 `CHROME_BIN`。

#### Snap / Flatpak 注意事项

`karma-chrome-launcher` 会直接 `exec` 浏览器二进制文件并传入其自身标志（包括临时的 `--user-data-dir`），因此沙箱化软件包需要额外处理：

**Snap** 可用，但不会被自动检测（启动器不会探测 `/snap/bin/chromium`）。请在 shell 配置文件中显式设置：`export CHROME_BIN=/snap/bin/chromium`

**Flatpak** 不推荐。没有可直接指向 `CHROME_BIN` 的普通可执行文件 —— 你需要用脚本包装 `flatpak run org.chromium.Chromium "$@"` —— 即便如此，沙箱也会阻止 Karma 的临时配置目录，因此通常无法启动。优先使用原生 Google Chrome 包（本方式）或 Chrome for Testing（方式 B）。

### 方式 B — 安装 Chrome for Testing 并设置 `CHROME_BIN`

将固定版本的 [Chrome for Testing](https://developer.chrome.com/blog/chrome-for-testing/) 构建安装到任意文件夹（以下示例均使用 `~/.cache/puppeteer`），然后将 `CHROME_BIN` 指向它：

```bash
npx @puppeteer/browsers install chrome@stable --path "$HOME/.cache/puppeteer"
```

建议使用 `--path` 标志：独立的 `@puppeteer/browsers` CLI 默认将下载位置设为**当前工作目录**，若不指定，你会在仓库内得到一个未跟踪的 `./chrome/` 文件夹，且下方的 `find` 将匹配不到任何内容。

将解析后的路径添加到 shell 配置文件（`~/.zshrc`、`~/.bashrc` 等），以便每个会话都设置该变量 —— 包括 git 钩子运行的非交互式 shell：

```bash
# Looks for the Chrome for Testing binary in ~/.cache/puppeteer/chrome, sorted by version so the latest version is picked if you happen to have multiple
export CHROME_BIN="$(find "$HOME/.cache/puppeteer/chrome" -name chrome -type f | sort -V | tail -n1)"
```

在 macOS 上，二进制文件名为 `Google Chrome for Testing`，位于 `.app` 包内，因此上面的 `-name chrome` 过滤匹配不到任何内容。请改用：

```bash
# Same idea, but matches the macOS executable inside the .app bundle
export CHROME_BIN="$(find "$HOME/.cache/puppeteer/chrome" -type f -name 'Google Chrome for Testing' -path '*Contents/MacOS*' | sort | tail -n1)"
```

重新加载 shell（或 `source` 配置文件）并验证：

```bash
echo "$CHROME_BIN"        # should print a path
"$CHROME_BIN" --version   # should print a Chrome version
```

设置好 `CHROME_BIN` 后，`npm test` 与 `git push`（通过钩子）无需额外配置即可工作。
