# 子任务

Super Productivity 中的子任务可将一项任务拆成更小的步骤，同时保持彼此关联：每个子任务都是真实任务，拥有自己的标题、时间跟踪与完成状态，但隶属于某个父任务。应用会维护清晰的父子关系，因此你可以展开/折叠层级、在父任务上查看汇总进度（例如剩余时间），并独立移动或完成子任务。了解子任务如何建模、有哪些限制，以及完成与移动如何工作，有助于你在项目、标签与今日视图中更有效地使用它们。

关于如何在界面中添加、重排、转换与管理子任务，见 [[2.04-Manage-Subtasks]]。关于父任务与子任务链接如何融入任务模型，见 [[4.09-Task-Attributes]]。

## 子任务如何建模

子任务是**独立任务**，与父任务双向链接。它们不是父任务内部的标签或行；每个子任务都有自己的 ID、项目、已用时间、备注与完成状态，与其他任务相同。差别在于关系：

- **子任务（子级）** 存储对父任务的引用。正是该链接使其成为子任务而非顶层任务。
- **父任务** 存储其子任务 ID 的有序列表。该列表中的顺序即展开父任务时所见顺序。

由于关系两侧均已存储，应用可快速显示父任务的子任务列表、在你完成或移动子任务时更新父任务，并在重组时保持层级一致。当你添加子任务、将子任务移到另一父任务，或删除父任务时，应用会同时更新子级的父引用与父级的子任务列表，使二者始终匹配。

子任务本身也可以有子任务（嵌套）：一项任务可以既是父又是子。同一双向链接适用于每一层。实践中，过深嵌套在界面中更难操作，在某些工作流（例如基于 markdown 的同步）中更深层可能被区别对待；应用设计上，一层或两层子任务是常见用法。

## 子任务的限制

并非每项任务都能变成子任务，部分行为也受约束，以保持模型一致。

### 不能转换为子任务的任务

两类任务**不能**转换为子任务：

- **重复任务** — 按日程重复出现的任务（例如每日或每周）不能成为另一任务的子任务。见 [[4.13-Repeating-Tasks]]。重复规则作用于单个任务；嵌套会与之冲突。
- **关联外部 Issue 的任务** — 已关联外部 issue（例如 Jira 或 GitHub）的任务不能成为子任务。Issue 链接是任务与 issue 的一对一关系；应用不以相同方式支持带 issue 链接的子任务。

若尝试将此类任务转为子任务（例如在基于 markdown 的工作流中缩进），应用会警告你，并保持其为顶层任务。你仍可在父任务下创建普通子任务，并将重复任务或关联 issue 的任务作为独立任务并列使用。

### 基于 Markdown 工作流中的深度与嵌套

当你使用基于 markdown 的工作流（例如 sync-md 插件），将缩进转换为父子结构时，深度由缩进层级决定。过深缩进可能被解释为备注内容或其他嵌套层级，而非额外的子任务层级。若依赖 markdown 导入/导出，将嵌套保持在一层或两层有助于按预期保留结构。

### 移动或复制时的继承与一致性

- **项目继承** — 每项任务（含每个子任务）恰好属于一个项目。当你**将子任务移到不同父任务**时，子任务会继承**新父任务的项目**。这样无需手动改项目即可使子任务处于正确项目中。若再移回另一不同项目中的父任务，它会依次继承该父任务的项目。
- **复制** — 当你**复制带有子任务的任务**时，应用会复制**整棵层级**：父任务及其全部子任务，使用新 ID 与相同的父子链接。复制出的子任务仍属于复制出的父任务，因此你得到结构的完整副本。

## 完成行为

父任务与子任务的完成方式会影响进度跟踪，以及删除或归档时发生的情况。

### 单独完成

子任务可**自行标记完成**。你可以在父任务之前或之后完成子任务：例如，先完成全部子任务再标记父任务完成，或先标记父任务完成并留下若干子任务稍后再做。应用不强制固定顺序。父任务的完成状态是独立的；通常在所有子任务完成时父任务被视为“完成”，但若需要也可提前完成父任务。时间跟踪与剩余时间汇总（预估减去已用时间）按子任务计算，并由未完成的子任务向上汇总到父任务，因此父任务的“剩余工作”反映其子任务剩余量之和。

### 级联删除

当你**删除父任务**时，应用会**同时删除其全部子任务**。不会要求你逐个删除；父任务与其子级一并移除。这样可避免留下孤立子任务并保持任务列表一致。若只想移除父任务但保留工作内容，可在删除父任务前将子任务移到另一父任务（或在工作流支持时将其转为顶层任务）。

### 标签视图中的标签与父子关系

标签视图（见 [[4.07-Tag-View]]）显示带有给定标签的任务。为避免同一工作出现两次并保持列表可控，当你**将子任务加入某标签**时，应用会**从该标签移除父任务**。因此标签视图在该标签中要么显示父任务，要么显示其子任务，而不会两者同时显示。这样你在标签中只看到一层任务，并避免重复或令人困惑的条目。若希望父任务与子任务同在一个标签中，该模式不受支持；应用为保持一致性，在标签视图中强制“一层”。

## 移动与重组

你可以**将子任务移到另一父任务**（或通过移除其父任务使其成为顶层任务）。此时：

- **旧父任务的子任务列表**会更新：移走的子任务从中移除。
- **新父任务的子任务列表**会更新：移入的子任务加入其中（若界面允许，按你选择的位置）。
- **子任务的父引用**更新为新父任务。
- **子任务的项目**设为新父任务的项目，如上所述。

这些更新一并发生，使移动后层级保持一致：不会有子任务出现在两个父任务的列表中，且每个子任务恰好指向一个父任务。在同一父任务内重排子任务仅改变父任务的子任务列表顺序；不会改变父引用或项目。

## 子任务出现在何处

子任务出现在任务列表中**其父任务之下**：项目视图、标签视图、今日视图等。通常可展开/折叠父任务以显示或隐藏其子任务。在任务详情面板中，打开父任务时可查看并编辑其子任务列表，并打开各个子任务。父任务与子任务属性（含时间预估与已用时间）会由 [[4.04-Schedule-View]] 与 [[4.08-Time-Estimates]] 使用，以便在适用处使父任务的剩余工作与时间线反映其子任务之和。
