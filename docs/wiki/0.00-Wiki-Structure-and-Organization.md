# Wiki 结构与组织

Wiki 采用 [[0.-Meta-Diataxis]] 中介绍的四种文档模式。带编号的文件名用于在 GitHub
Wiki 中把页面归组在一起，不要随意重命名，因为现有链接和书签都依赖这些名称。

## 分区

- **0 — Meta：** 贡献、结构、风格与维护相关指南。
- **1 — Quickstarts：** 面向首次成功走通工作流的引导式学习路径。
- **2 — How-to guides：** 完成某一具体任务的聚焦步骤。
- **3 — Reference：** 对设置、API、快捷键、平台差异以及受支持集成的事实性说明。
- **4 — Concepts：** 理解产品行为所需的背景与心智模型。

[[Home]] 与 [[_Sidebar]] 是导航入口。每个编号分区还有索引页，例如 [[1.00-Quickstarts]]、[[2.00-How_To]]、
[[3.00-Reference]] 和 [[4.00-Concepts]]。

## 添加或更新页面

1. 选择与页面目的匹配的分区。
2. 使用一个清晰的 H1，并遵循 [[0.01-Style-Guide]]。
3. 将该页链接到其分区索引；若属于主要用户路径，也要从 [[_Sidebar]] 链接。
4. 对照当前仓库核对命令、路径、设置与行为。
5. 提交变更前遵循 [[0.02-Wiki-QA-and-Maintenance]]。

避免占位页和照搬的配置转储。一份简短、持续维护、并链向权威代码或指南的页面，
优于日后容易过时的冗长详述页。
