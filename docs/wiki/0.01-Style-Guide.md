# 风格指南

本文概述这些 Markdown 笔记所采用的部分结构与格式约定。要在 CommonMark、GitHub-Flavored Markdown、GitHub 内置 Wiki 限制以及 Obsidian-Flavored Markdown 之间保持兼容，需要刻意维护，否则难以相对轻松地迁移到其他服务（例如其他 Wiki 程序、通过静态站点生成器部署的 GitHub/Cloudflare Pages 等）。

下文许多限制（尤其是路径与命名）源于 GitHub Wiki 对所接收笔记的清洗与重组方式。

另见：[[0.-Meta-Diataxis]]（所用文档框架入门），以及 [[0.00-Wiki-Structure-and-Organization]]（如何为 Wiki 撰写笔记的更多细节）。

## 扁平结构与绝对路径

只有使用 Wiki 风格链接时，嵌套目录才相对可靠。若笔记位于不同子目录，没有机制能防止重名：GitHub 会把 `Dir1/note.md` 与 `Dir2/note.md` 折叠成同一个笔记，另一个将无法访问。

因此：除图片及其他文件外，所有笔记都应“扁平”放在 `docs/wiki` 内；图片等可放在子目录，因为 GitHub 不必把它们渲染为独立页面。存放在 `docs/wiki/assets` 有助于让 `docs/wiki` 根目录更整洁。

```txt
vault/
├─ 1.01-First-Steps.md
├─ 2.09-Configure-Sync-Backend.md
│
├─ assets/
│  ├─ 1.01-First-Steps-start-time-tracking.png
│  ├─ diagrams/
│     ├─ flow.png

```

## Wiki 风格链接

Markdown 链接冗长且不便他人手敲。若链接是自动生成的则问题不大。因此笔记与图片强制使用 Wiki 风格链接。GitHub 与 Obsidian 之间的主要差异是：GitHub 不需要使用 `!`。

以下两者均有效：  
根目录：`[[image-at-root.png]]`  
嵌套图片：`[[images/image.png]]`

如上所述，把图片嵌套存放可减少杂乱，因此更推荐这样做。

### 别名

形如 `[[9.Test-Note|Test Note]]` 的链接会把路径渲染成类似 `../wiki/Test-Note` 的 URL，且无法解析到任何内容。不要使用该语法。

## Lint

有 GitHub Action 使用 `pymarkdownlnt` 对所有 Markdown 做 lint。若条件允许，提交 PR 前请对全部文件运行 `pymarkdownlnt --disable-rules line-length scan --recurse ./docs/wiki`。在 Arch 上只需 `pipx install pymarkdownlnt`。理想情况下配置为 pre-commit hook，以确保每次提交都能通过 CI。

下面这个简单 hook 即可：

```md
cat > .git/hooks/pre-commit <<'EOF'
#!/bin/sh
set -eu

pymarkdownlnt --disable-rules line-length scan "docs/wiki"
EOF

chmod +x .git/hooks/pre-commit
```

### 让某些笔记豁免 H1 规则

Lint 规则 **MD041**（文件第一行应为顶级标题）可对特定笔记关闭，使其不必以 H1 开头。

**按笔记：** 在笔记**第一行**加入此 HTML 注释（前面不要有空行）：

```md
<!-- pyml disable md041 -->
```

该 pragma 在解析前会被剥离，因此不影响渲染。仅该文件豁免 MD041。

**整个 Wiki：** 若要关闭所有 Wiki 笔记的 H1 要求，在 `.github/workflows/wiki-sync.yml` 的 `--disable-rules` 列表中加入 `md041`（例如 `--disable-rules line-length,no-inline-html,md041`）。此时无需按笔记添加 pragma。

也可使用 Obsidian 的 “Linter” 插件做额外 lint。详见 [[2.10-Configure-Obsidian-for-Wiki-Contributions#plugins]]。

## 缩进

禁止使用 Tab。

仅使用两个空格。

## 空格与短横线

在 Obsidian 侧将所有空格替换为短横线。GitHub 会自动这样做；主动这样做更好，可避免诸如 `API Reference.md` 与 `API-Reference.md` 之类的潜在笔记冲突。若被 GitHub 检测到，其中之一会被静默丢弃，或至少无法通过常规链接访问。

## 锚点链接

与笔记类似，锚点在单篇笔记内是扁平的。空格会变成短横线，大写也会变成小写。若试图为每个子标题都维护唯一、扁平的引用，笔记会变得很难看。如果有办法校验标题以防止重复，会稍容易一些。请谨慎使用锚点；更推荐把笔记写短，从而避免需要深度嵌套的引用。
